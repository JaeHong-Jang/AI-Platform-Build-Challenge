# B010 이삿짐 점검 2D 장면

1. 이삿짐 점검 UI에서 AI가 실제로 움직이는 모습 — 인원 배치 그림이 아니라 **집에서 트럭까지 짐을 실어 옮기는 2D 장면**, 더 디테일하게.
2. 색은 **더 진한 남색** → AskUserQuestion으로 A '진남색' 선택: 배경 #EDF1F7 · 레일 #0B1836 · 레일 선택 #1C3363 · 레일 글자 #B7C4DE · 버튼 #1B3A8C · 버튼 연한 #E0E7F5 · 글자 #0E1A33 · 트럭 #C2410C (흰 글자 대비 10.3, 본문 15.3).
3. 에이전트 팀을 지휘관 + 3팀×3 구조로 두지 말고 **TRITON 팀 구조**로: 역할별 에이전트가 실행 흐름 순서대로 일하고 각 단계에 행위자(AI·코드·사람)를 붙인다. 증거 검증관(코드)과 사람 최종 승인을 둔다 (TRITON `agents/README.md`, `ControlPipeline.tsx`).
4. **한 페이지**: 입력(조건 한 줄 + 견적서) → 에이전트들이 짐을 옮기는 모션 → 그 결과로 견적 점검 결과.
5. 결과는 '견적 점검 결과'(사용자 선택): 원문에서 확인된 총액·계약금 + 트럭에 실린 짐(명시됨) / 멈춘 짐(추가요금 위험). **가격을 새로 계산하지 않는다.**

## 설계
- 에이전트 10개 = AI 3 · 코드 7 (지휘관 → 원문 검증관으로 교체, 원문 검증관은 끌 수 없음). 흐름: 01 조건 해석(AI) → 02 짐 목록 → 03 견적 읽기(AI) → 04 원문 검증 → 05 대조·적재 → 06 질문 작성 → 07 답변 점검(AI) → 사람 승인 / 보조 08 견적 비교 · 09 계약 점검 · 10 서류 안내.
- 장면: 출발 건물 단면(층수·엘리베이터/계단은 입력 조건대로) → 현관 앞 짐 → 검수대(견적서·원문 검증) → 멈춤선(질문 게시판) → 트럭 적재함. 상자 1개 = 짐 확인 항목 1개, 작업 조건·추가비는 위쪽 표지.
- 시간 커서 하나로 그린다(이벤트 큐 없음) — `lib/scene.ts` 순수 함수 + 시험. LLM 단계는 실제 호출 시간 동안 해당 캐릭터가 일한다.
