# B006 이사 지킴이 웹 구현 설계와 프로토타입

- **출발점**: 사용자 — "웹으로 만드는 게 더 나을 것 같다(앱은 너무 오래 걸린다). 내 다른 공모전 폴더의 코드를 다 참고해서 어떻게 웹으로 구현할지, 어디에 AI Agent를 어떻게 써서 사용자에게 줄지, 왜 이 문제를 잡았고 어떤 문제를 해결하는지 명확히 해 달라"
- **전제**: D003 (모바일 웹, P0 4단계, AI는 비정형 구조화·판정은 규칙)
- **질문**
  1. 사용자의 기존 공모전 웹 코드(맛대패스·TRITON·TTA·성남 KAIST·MoveValue·VISTA·SL)에서 그대로 가져올 스택·구조·LLM 호출·에이전트 패턴은 무엇인가
  2. 이 서비스에서 AI Agent가 **진짜로 필요한 자리**는 어디이고(장식이 아니라), 사용자는 그 결과를 어떤 화면으로 받는가
  3. 문제 정의를 한 문장으로 — 누가, 언제, 무엇 때문에 손해를 보는가, 우리는 그중 무엇을 해결하고 무엇을 하지 않는가
- **범위**: 조사(Sonnet 2: 기존 코드) ∥ 분석(Sol: 에이전트 배치·문제 정의) → 의장 통합 설계 → 프로토타입 웹 구현 → 지휘부 기술 검증(Argon)
- **성공 기준**: 로컬에서 실제로 동작하는 웹 프로토타입(사진·견적 업로드 → 확인 → 대조 카드 → 확인 문구), 설계 문서에 기존 코드 근거(file:line)와 에이전트 배치 이유가 있을 것
- **주의**: 본선 사전 코딩 허용 범위는 unknown — 이번 프로토타입은 예선 기획서용 화면·검증용이며, 허용되지 않으면 본선 당일 다시 구현한다
