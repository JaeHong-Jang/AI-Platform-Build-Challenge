# B008 이사 지킴이 v0.3 — 에이전트 관제형 재설계

- **출발점**: 사용자 — "실제 사람들이 이사하는 거 UI로 보여주게. 조건들 입력하면 입력한 거 토대로 홈 화면 만들고, 에이전트 팀 구조로 오케스트라 한 명 + 작업하는 3명 3명 3명, 온톨로지로 근거 그래프, AI 기능 더 늘리기. 조건을 입력하면 에이전트가 실제로 이삿짐을 움직이는 UI를 보여 주면서 서류·문서 산정하는 걸 보여 주고, 선택은 매우 완화, 왼쪽에 에이전트 활성화/비활성화, 어떤 업체를 쓰면 좋을지도 기능으로 — 처음부터 업체를 정해 두지 말고. TRITON 웹사이트를 참고해 디자인하되 이사에 맞는 색감을 고를 것"
- **해석 (의장)**
  1. 흐름이 바뀐다: v0.2는 "이미 받은 견적 1건"에서 시작했다 → v0.3은 **조건(집 크기·층·엘리베이터·날짜·주소 구) 입력**에서 시작해 에이전트가 짐·차량·인원·서류를 산정하고, 그 뒤 **업체 비교·선택**까지 돕는다.
  2. 앱 안의 에이전트: 오케스트레이터 1 + 3팀 × 3명. 왼쪽 레일에서 켜고 끈다. 로컬 Ollama(8GB GPU, qwen3:4b·ax4-light)라 10개 모두 LLM이면 느리다 → 결정적 도구 에이전트와 LLM 에이전트를 정직하게 구분해 표시한다.
  3. 화면: TRITON(2D 법정 장면 `scene2d/`, 작업실 `AgentsPage`, 온톨로지·근거 그래프 `features/ontology`, 관제 파이프라인 `features/control`) 구조를 이사 도메인으로 옮긴다. 장면 = 출발 집 → 트럭 → 도착 집, 에이전트가 짐을 옮기며 산정 결과가 쌓인다.
  4. 입력 부담 완화: 집 유형 하나 고르면 기본 짐 목록 자동, 자연어 한 줄("원룸, 3층 엘베 없음, 냉장고·세탁기·침대")을 에이전트가 조건으로 바꾼다. 사용자는 고치기만.
  5. 업체 추천: 실제 업체 목록·평점을 지어내지 않는다. 공개 자료(허가 확인 방법, 보험, 소비자원 권고)와 사용자가 받은 견적 여러 건 비교로 "고르는 기준"을 준다.
- **조사 (병렬)**: Sonnet A — TRITON 프론트엔드 화면·코드 구조(장면·작업실·그래프·레일) / Sonnet B — TRITON 구조 위 이사용 팔레트 후보 3안(hex·역할·대비) / Sol — 산정·업체 선택 근거 자료(부피·차량 톤수, 허가 조회, 표준약관 서류 항목, 공개 데이터 여부)
- **분석 → 검증**: 1+3×3 에이전트 구성·화면 명세 → Argon(구현성)·Astra(심사) 리뷰
- **보고 후 구현**: 팔레트는 사용자가 고른 뒤 구현, 보고 값과 구현 값을 한 줄씩 대조
- **제약**: 예선 기획서 PDF 마감 2026-10-25 23:59(참가신청 17:00). 이번 설계는 기획서 내용이 되고, 구현은 본선(11/27)까지 이어진다.
