# 이사 지킴이 웹 설계 (B006)

과정: 조사([[Sonnet]] 2명 — 사용자의 기존 공모전 코드 7개) ∥ 분석([[Sol]] — 에이전트 배치·문제 정의) → 의장 통합·구현([[Opus]]) → 지휘부 기술 검증([[Argon]]). 전제는 [[이사-지킴이-제작계획]](D003).
코드: `web/` · 실행: `cd web && npm run build && npm run start` → http://127.0.0.1:3100

## 1. 무슨 문제를, 왜
> **비대면 견적을 받은 소규모 이사 이용자가 계약금을 보내기 전에, 짐과 작업 조건이 문서에 충분히 적혀 있는지 확인하기 어려워 당일 추가요금 요구와 이사 거부에 대비하지 못하는 문제.**

| | 내용 | 근거 (소비자원 첨부 PDF, `wiki/sources/kca2026-소규모이사-피해.md`) |
|---|---|---|
| 누가 | 방문견적 없이 사진·전화·온라인으로 견적을 받은 원룸·소형 이사 청년 | 소규모 이사 241건 중 20~30대 65.1% (p1) |
| 언제 | 업체를 고른 뒤, 계약금 보내기 직전 | — |
| 원인 | 짐·작업 조건·비용 포함 범위가 문서에 안 적힘 | 비대면 계약이라 추가비용 피해에 더 취약 (p5) |
| 손해 | 당일 "짐이 많다·계단이다" → 추가 비용, 거부하면 이사 거부 | 추가 비용 요구 70건·24.9%(중복 집계 281건), 계약불이행으로 이어지는 사례 많음 (p2·p5) |
| 공식 권고 | **"계약서에 이사화물 내역, 작업인원 수, 추가서비스 내역 및 비용 등을 상세히 기재하여 추가요금 요구 등 향후 분쟁에 대비한다"** | p8 소비자 주의사항 |

**한 줄 포지션: 소비자원이 "상세히 적으라"고 권고하는 것을, 실제로 할 수 있게 만드는 도구.** 소비자는 무엇이 빠졌는지 모른다 — 우리는 내 짐 사진과 견적서를 대조해 빠진 것을 찾아 준다.

| 해결하는 것 | 해결하지 않는 것 |
|---|---|
| 사진 속 짐이 견적서에 포함됐는지 확인할 항목 찾기 | 부피·톤수·적정 가격 산정 |
| 층수·계단·사다리차·운반 거리의 기재 여부 점검 | 현장 실측, 인력·장비 적정성 판정 |
| 추가 비용의 조건·금액을 업체에 묻는 문장 | 추가요금 차단, 위법 판정, 배상액 계산 |
| 업체 답변에서 답한 것과 안 한 것 가르기 | 무응답·"다 포함"을 개별 합의로 간주 |
| — | 파손·분실(피해 1위 47.7%) 배상, 분쟁 대행 |

## 2. AI를 어디에, 어떻게 — 단계별 배치
에이전트는 "목표를 받아 허용된 도구를 고르고, 결과에 따라 다음 행동이나 종료를 정하는 제한된 실행 주체"로 정의한다(Sol). 여러 호출을 병렬로 하는 것은 에이전트가 아니다.

| 사용자 단계 | 방식 | 왜 | 사용자가 받는 화면 | 코드 |
|---|---|---|---|---|
| ① 사진·견적서 올리기, 현장 조건 | 규칙 | 형식·용량·필수값 검사로 충분 | 미리보기, "아직 모르는 것" 안내 | `image.ts`, `rules.ts missingFacts` |
| ② 방 사진 → 짐 목록 | **AI 호출 1회** (이미지→JSON) | 비정형 사진의 구조화는 AI만 가능 | 품목·수량·사진 번호·"개수 확인 필요" | `extract.ts extractItems` |
| ③ 견적서 → 항목·원문 발췌 | **AI 호출 1회** (②와 동시) | 손글씨·캡처 등 제각각인 견적서 | 견적서 원본 옆 교정 폼 | `extract.ts extractQuote` |
| ④ 초안 교정 | 사람 | AI는 개수 세기·작은 글씨에 약함 | "AI 초안" 표시, ± 버튼, 옮김 체크 | `App.tsx` 2단계 |
| ⑤ 대조 | 규칙 (LLM 없음) | 같은 입력 → 같은 결과, 없는 조항 불가 | 4상태 카드 + 원문 발췌 + 참고 조항 | `rules.ts compare` |
| ⑥ 확인 요청 문장 | 문장 틀 + 금지표현 가드 | 자유 생성 불필요, 단정·위협 차단 | 복사 버튼, 단정 표현 경고 | `message.ts` |
| ⑦ **업체 답변 점검** | **에이전트** (도구 4개, 상한 8회) | 답변은 일부만 답하거나 조건을 달거나 뭉뚱그림 → 남은 카드마다 근거를 찾고, 거절되면 고쳐 다시 제출 | 에이전트가 한 일(도구 기록), 반영 후보 승인, 남은 것만 다시 묻는 문장 | `agent.ts reviewReply` |

**에이전트 도구 계약** (`web/src/lib/agent.ts`)
- `get_open_cards` 확인이 남은 카드 · `find_in_reply` 답변에서 관련 문장 찾기 · `propose_updates` 갱신 후보 제출 · `finish` 요약
- 코드 검증: quote가 답변 원문에 그대로 있어야 함, `명시됨`으로 바꾸려면 그 항목 이름이 문장에 있어야 함("다 포함이에요"로 전자레인지를 명시됨 처리 → 거절), 상태 변경은 사용자가 승인해야 반영
- 상한: 도구 8회·대화 6턴. 외부 전송·웹 검색 도구 없음. 답변 속 지시문은 데이터로만 취급

심사 질문 "왜 AI 에이전트인가"에 대한 답: 에이전트는 업체 답변을 조회하고, 아직 확인되지 않은 항목에 따라 다음 도구와 대상을 고릅니다. 일부만 답하면 그 항목의 갱신 후보만 만들고 나머지는 미확인으로 남겨 다시 묻게 합니다. 근거 수집과 확인 순서는 에이전트가, 최종 상태는 규칙과 사용자 확인이 통제합니다.

## 3. 웹 구현 — 기존 코드에서 가져온 것
조사 원문: `runs/out/b006-ref-a.sonnet.md`(맛대패스·TRITON·TTA), `runs/out/b006-ref-b.sonnet.md`(성남 KAIST·MoveValue·VISTA·SL). 일곱 프로젝트 모두 **이미지→LLM 구조화 코드는 없었다** — 그 부분만 새로 짰다.

| 가져온 것 | 출처 (사용자 기존 코드) | 이사 지킴이에서 |
|---|---|---|
| 스택: Next.js 16.3.4 · React 19.3 · zod 4.6.1 | 성남 KAIST `package.json` | `web/package.json` |
| zod → JSON 스키마 강제 + 응답 재검증, 재시도 없음 | 성남 KAIST `src/lib/provider.ts:54-148` (callModel) | `provider.ts callModel` + 이미지 블록 추가, 예산 모델은 제외 |
| 판정은 코드, LLM은 구조화 / 입력 없으면 unknown | MoveValue `api/jeonse_safeguard.py:188-236` | `rules.ts` 4상태, `판독 불가` |
| 고정 문장 틀 + 변수 주입 | MoveValue `jeonse_safeguard.py:417-480` | `message.ts composeRequest` |
| 금지·단정 표현 가드 | 맛대패스 `agents/verify/wording-guard.ts:10-37` | `message.ts guard` |
| 생성→검증→재생성 루프, 실패 시 안전 폴백 | TTA `src/agent/loop.ts:48-110` | 에이전트 `propose_updates` 거절 → 재제출 |
| replay(예시) 어댑터, 키 없이 전 기능 실행 | TTA `src/agent/llm.ts`, 성남 `src/lib/fixture.ts` | `mode()` preview + `fixtures.ts`, 화면 배지 상시 |
| 요청 본문 검사 (zod 실패 → 400) | 성남 KAIST `src/lib/http.ts:9-95` | `http.ts` (장수·크기 상한) |
| "AI 제안은 사람이 눌러야 반영" | 맛대패스 `frontend/src/features/intake/FreeTextParse.tsx` (88줄 — 조사 보고의 121-190줄 인용은 틀림) | 2단계 교정, 5단계 반영 승인 |
| 복사 버튼·실패 시 수동 복사 안내 | 맛대패스 `shared/ui/CopyButton.tsx` | `App.tsx copy` |

가져오지 않은 것: MoveValue의 범용 도구 루프·Ollama, TRITON의 대형 상태 스토어, TTA의 6천 줄 CSS·다크 테마, 성남의 SQLite·이미지 저장(사진 무저장 원칙과 충돌), VISTA 서비스워커 캐시(개인 사진이 남을 위험).

## 4. 구조
```
web/src/
  app/page.tsx, layout.tsx, globals.css      모바일 우선(최대 560px), 라이트 단일 테마, Noto Sans KR
  app/api/extract/items  POST 방 사진 1~3장 → 짐 초안       ┐ 브라우저에서 Promise.all 동시 호출
  app/api/extract/quote  POST 견적서 1장 → 항목 초안        ┘ (각 요청이 용량 한도 아래)
  app/api/reply          POST 카드 + 업체 답변 → 에이전트 실행 기록·반영 후보
  app/api/mode           GET  live | preview
  components/App.tsx     5단계: 올리기 → AI 초안 확인 → 확인할 것 → 업체에 묻기 → 답변 점검
  lib/types.ts           모델 출력 계약(zod)·카드 4상태
  lib/rules.ts           대조 규칙 3개(품목·작업조건·추가비) + 빠진 사실 질문
  lib/references.ts      참고 조항(법제처 설명 기준, 예외 요건 포함) — 모델은 조항을 쓰지 않음
  lib/message.ts         확인 요청 문장 틀 + 금지표현 가드
  lib/provider.ts        Anthropic Messages 호출(구조화 출력·25초 타임아웃)
  lib/extract.ts         추출 프롬프트, preview면 예시 초안
  lib/agent.ts           업체 답변 점검 에이전트(도구·검증·상한)
  lib/image.ts           브라우저 축소(긴 변 1280px, JPEG, 장당 ~400KB, EXIF 제거, HEIC 실패 안내)
  lib/rules.test.ts      규칙·가드·에이전트 테스트 10개
public/samples/          가상 방 그림 2장·가상 견적서 (예시 모드용, "예시 그림"·"가상 견적서" 표기)
```
실시간 분석: `web/.env.local`에 `ANTHROPIC_API_KEY`(필요 시 `ANTHROPIC_MODEL`)를 넣고 다시 실행. 키가 없으면 모든 화면에 "예시 결과 · API 키 없음" 배지.

## 6. 지휘부 기술 검증 (Argon, `runs/out/b006-review.argon.md`) → D004
