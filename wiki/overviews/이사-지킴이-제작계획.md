# 이사 지킴이(가칭) 제작 계획 — B005 / D003

과정: 조사([[Sol]] 문제 근거·약관 ∥ [[Sonnet]] 경쟁 벤치마킹) → 분석(각자 제작 계획) → 상호 검증(Sol↔Sonnet) → 지휘부 검증([[Astra]] 전략·심사 ∥ [[Argon]] 기술, 블라인드) → 토론(갈린 3쟁점) → 판정([[Opus]], D003). 출발점은 B004에서 사용자가 고른 "이삿날 '이건 추가요' 없게". 이전 판정은 [[아이디어-재설계-B003]].

## 1. 한 줄 정의
> **계약금 보내기 전에, 내가 받은 이사 견적서를 내 짐 사진·작업조건과 대조해 추가요금으로 이어질 수 있는 미확인 사항을 찾고, 업체에 보낼 확인 요청으로 바꿔 주는 모바일 웹.**

- 주 사용자: 방문견적 없이 사진·전화·문자로 견적을 받은 원룸·소형 주거 이사 청년
- 쓰는 순간: **계약 직전**(핵심). 견적 받을 때는 보조, 이사 당일은 P1
- 약속하지 않는 것: 추가요금 차단, 위법 판정, 배상액 계산, 부피·톤수 산정

## 2. 왜 이 문제인가 — 근거 (원문: `wiki/sources/kca2026-소규모이사-피해.md`)
| 사실 | 수치 | 쓸 때 주의 |

| 소규모 이사(10만~100만 원) 분석 대상 | 2025년 241건 | |
| 청년 비중 | 20~30대 65.1%(157건), 20대 22.8% — 전체 이사 이용자의 20대 비율 11.6%의 약 2배 | 신청자 연령 분포 |
| 추가 비용 요구 | 70건, **24.9%** | 분모는 유형별 중복 집계 **281건**. 241건을 분모로 쓰지 않는다 |
| 피해 유형 1위 | 물품 파손·분실 47.7%(134건) | 심사 질문 대비 (§11) |
| 연쇄 피해 | 추가비용 거부 → 업체 계약불이행으로 이어지는 사례 많음, 비대면 계약이라 더 취약 | 소비자원 원문 p5 서술 |

## 3. 기존 서비스와 차이 — 정직한 비교
| 기존 서비스 (공개 자료로 확인한 범위) | 우리 |
|---|---|
| **Agoyu**: AI 짐 조사, 항목별·상한 견적, 변경 기록, 분쟁 지원 ([FAQ](https://agoyu.com/faqs/)) | 업체를 다시 고르지 않고, **이미 받은 외부 견적서**를 대조 |
| **Yembo**: 업체용 영상 짐 조사 → 견적·고객 확인 ([소개](https://yembo.ai/moving/surveys)) | 소비자가 직접 쓰는 도구 |
| **짐싸·숨고**: 견적 비교·중개 | 업체 선택 **후**, 계약 직전 문서 점검 |
| **미소**: 방문 영상·표준 견적·분쟁 증빙 (보도) | 한국 이사화물 표준약관을 참고한 확인 질문 |
| **내집이사·노블로지스**: 사진 기반 AI 견적 (보도 시점 기능) | 견적을 내는 게 아니라 받은 견적의 빈칸을 찾음 |

**차별점 문장(최종)**: 기존 Agoyu·Yembo는 공개 소개상 짐 조사와 견적·확인·분쟁 지원까지 제공하며, 우리는 소비자가 이미 받은 외부 견적서를 자신의 짐 사진·작업조건과 대조해 한국 이사화물 표준약관을 참고한 확인 요청으로 바꾸는 데 집중합니다.
금지 표현: "국내 최초", "기존은 견적만", "경쟁 없음". 경쟁사의 외부 견적 대조 기능 유무는 **unknown**.

## 4. 웹이냐 앱이냐 — 모바일 웹
Sol·Sonnet·Astra·Argon 만장일치. 계약 직전 한 번 쓰는 도구라 설치 장벽이 치명적이고, 문구 복사·QR 시연·9시간 배포에 웹이 유리하다. PWA 설치·영상 녹화는 쓰지 않는다. iOS `capture` 촬영과 카카오톡 인앱 브라우저 동작은 실기기 확인 전 가설 → 촬영/앨범 선택 분리, 인앱 감지 시 외부 브라우저 안내.

## 5. 기능 범위
| 등급 | 기능 |
|---|---|
| **P0** ① 입력 | 방 사진 1~3장, 견적서 이미지(JPEG/PNG) 1장, 출발·도착지 작업조건(층수·엘리베이터·사다리차·주차거리·분해설치) |
| **P0** ② 사용자 확인 | AI 초안을 원문 옆에서 수정 — 품목·수량·운송 여부·같은 물건 중복 / 총액·차량·인원·장비·포함 문구 |
| **P0** ③ 대조 | `명시됨 / 포함 여부 미확인 / 조건 모호 / 판독 불가` 카드 |
| **P0** ④ 확인 요청 | 고른 카드 → 검토한 문장 틀 → 복사. 같은 화면에 근거(사진·견적 발췌·참고 조항) |
| P1 | 별도 당일 화면·저장, 업체 답변 첨부·재점검, 공유 링크, 영상 → 정지사진, PDF, 출발 전 물품 상태 사진 첨부 |
| P2 | 다중 견적 비교, 전자서명, 업체 매칭, 임대차 흠집·보증금 |

원칙: 견적에 "가구 일체"라고 적혀 있으면 책장을 '누락'으로 단정하지 않고 "문서만으로 포함 여부 확인 어려움"으로 표시한다. 업체 답변 전에는 '합의 완료'로 표시하지 않는다.

## 6. AI · 규칙 · 사람의 역할
| 단계 | AI | 규칙 | 사람 |
|---|---|---|---|
| 짐 파악 | 사진 속 품목 후보·수량·사진 번호 | 품목 사전 정규화(책꽂이↔책장) | 실제 수량·중복·운송 여부 확정 |
| 문서 읽기 | 견적서 → 고정 JSON + 원문 발췌 | 금액·단위·필수 필드 검사 | 원문과 숫자 대조 |
| 대조 | — | 3개 확인 규칙 | 애매한 연결 확정 |
| 확인 문구 | — | 검토한 문장 틀 + 조항 번호 주입 | 수정·전송 |
| 적법성·배상 | 하지 않음 | 참고 조항만 연결 | 필요 시 1372 소비자상담 등 |

발표 메시지: **AI는 비정형(사진·견적서)을 구조화하고, 판정은 규칙이 통제한다.** 그래서 없는 조항이나 "불법" 단정이 나올 수 없다.

## 7. 아키텍처
```
[모바일 웹 · Next.js]
 입력(촬영/앨범) → 브라우저 전처리: 디코딩 검사(HEIC 실패 시 JPEG 안내) · 긴 변 ≤1280~1568px JPEG · EXIF 제거
                   · 장당 ≤400KB, 요청당 ≤3MB (Vercel 함수 4.5MB 한도)
   ├─ POST /api/extract-items ─▶ 모델 호출 ① 방 사진 → {품목, 수량, 크기, photoIds, 낮은 확신}
   └─ POST /api/extract-quote ─▶ 모델 호출 ② 견적서 → {총액, 계약금, 차량, 인원, 장비, 포함 문구, 추가비 조항, 원문 발췌}
        (두 호출 Promise.all 병렬 · 서버는 이미지 저장 없이 응답 후 폐기)
 사용자 확인·교정 화면 → 규칙 엔진(rules.json + TS, LLM 호출 없음, 즉시) → 카드 → 문장 틀 → 복사
 상태는 sessionStorage에만. 18~20초 지연 시 "[사전 실행 결과]" 배지를 단 미리 돌린 결과로 전환
```
모델: 이미지 입력과 JSON 스키마를 지원하는 모델 1개를 얇은 어댑터로 감싸고, 준비 기간 실측 후 확정. 전용 OCR(CLOVA·Upstage)은 모델이 한국어 견적서에서 실패할 때만 채택. "우리 서버 미저장"이 "외부 API 무보관"을 뜻하지 않음을 업로드 화면에 고지.

## 8. 확인 규칙 3개 (참고 근거: 법제처 생활법령 표준약관 설명 — 공정위 원본 대조 전)
1. **짐 품목 포함 여부** — 사용자가 확정한 대형·분해 품목이 견적 원문에 명시됐는가 (제4조 기재 사항 참고)
2. **작업조건·차량·인원·장비 기재 여부** — 층수·계단·엘리베이터·사다리차·주차거리가 적혀 있는가. '필수항목 전체 검사'라고 표시하지 않는다
3. **추가비 발생 조건 확인 질문** — 제5조 제3항(고객 요청에 따른 산정 사항 변경 + 사전 고지), 제8조 제2항(고객 책임 사유 + 사전 고지), 제8조 제3항(수고비 등 추가 청구 제한)을 **예외 요건까지** 붙인 참고 안내

시연용 문장 틀 예(가상 사례): "첨부 목록의 책장 1개를 포함한 운송과 출발지 3층 계단 작업이 총액 35만 원에 포함되는지 확인 부탁드립니다. 별도 비용이 있다면 항목·발생 조건·금액 또는 산정 방식을 계약 전에 적어 주세요."

## 9. 평가 — 제안 목표(실측 아님)
- 권한 있는 자체 방 사진 + 가상 견적서. 개발용과 최종 평가용을 **방 단위로 분리**
- **AI 단독 결과와 사용자 교정 후 결과를 따로** 보고, 실패·시간초과도 분모에 포함
- 지표: 품목 재현율·정밀도, 견적 필드 정확도, 미확인 사항 탐지율, **정상 견적 오탐(문서당 1개 이하)**, 처리 시간, 처음 보는 사용자 완료율, 금지 출력 0건
- 실제 추가요금 감소 효과는 **unknown** — 후속 실사용 평가로 확인한다고 쓴다

## 13. 기획서 5항목 초안 (지휘부 검토 반영)
① **문제와 주요 사용자** — 한국소비자원에 접수된 이사서비스 피해구제 신청은 2023년 603건, 2024년 785건, 2025년 961건이었다. 2025년 소규모 이사 241건에서 신청자의 65.1%가 20~30대였고, 피해 유형별 집계(중복 포함 281건)에서 추가 비용 요구는 70건·24.9%였다. 소비자원은 추가비용을 거부하면 업체가 이사를 거부하는 계약불이행으로 이어지는 사례가 많다고 밝혔다. 우리는 비대면 견적을 받고 계약금을 보내려는 청년을 주요 사용자로 설정했다.
② **핵심 기능과 이용 흐름** — 사용자가 방 사진과 받은 견적서를 올리면 AI가 짐 목록과 견적 항목의 초안을 만든다. 사용자가 확인·수정하면, 서비스는 포함 여부가 불명확한 항목을 근거와 함께 보여 주고 업체에 보낼 확인 요청 초안을 만든다. 업체 답변 전에는 합의 완료로 표시하지 않는다.
③ **AI 적용 방식·데이터·기술 구성** — 이미지 입력 모델이 사진과 견적서를 고정 형식으로 구조화하고, 검토한 규칙이 기재 상태와 확인 사항을 표시하며 관련 표준약관 조항을 참고로 연결한다. 이미지 모델의 개수 세기·작은 글씨 인식 한계 때문에 사용자 확인을 필수 단계로 둔다. 모델 학습 없이 권한 있는 자체 사진과 가상 견적서를 사용하며, 모바일 웹(Next.js)으로 구현한다. 서비스 서버에는 사진을 저장하지 않으며, 외부 AI 제공사의 처리 조건은 별도로 고지한다.
④ **구현 계획·역할 분담·기대 효과** — 본선 당일에는 제한된 이미지 입력부터 확인 문구 복사까지 구현하는 것을 목표로 하며, 12시·15시 점검 시점에 범위를 줄이는 기준을 미리 정했다. 준비 기간에는 약관 원문 대조, 평가셋, 실기기 검증을 진행한다. 자체 평가에서는 미확인 사항 탐지율·정상 견적 오탐·문서 추출 정확도·처리 시간을 AI 단독과 사용자 교정 후로 나눠 측정한다. 추정: 계약 전에 확인할 사항을 구체화하는 데 도움이 될 수 있으며, 실제 추가요금 감소 효과는 후속 실사용 평가로 확인한다.
⑤ **외부 자료·오픈소스·AI 도구 출처** — 한국소비자원 피해예방주의보(2026-04-21) 및 첨부 자료, 법제처 생활법령정보의 이사화물 표준약관·소비자분쟁해결기준 설명, 사용 모델의 공식 문서, 채택 오픈소스의 이름·버전·라이선스. 공정위 원본 대조가 끝나지 않은 조항은 검증 완료로 표시하지 않는다.
