# 추천 아이디어 15선 — 상세 카드

순위·점수 근거는 [[아이디어-최종추천]]. 수치는 [[Sol]] 검증본만 사용했고, 해외 수치는 "배경"으로 표시했다. 논문은 모두 arXiv API로 실재 확인([[논문-허브]]).

공통 설계 원칙: **AI는 읽기·연결·설명, 금액·법·안전 판단은 결정론적 규칙, 최종 확인은 사람.**

---

## 1. [[L03-임금-누락-증거-복원|L03]] 근무 타임라인 복원·임금 차이 근거표 — 4.48
- **사용자**: 근무표가 자주 바뀌는 아르바이트생·이주노동자, 그리고 이들을 상담하는 노동권익센터·노무사
- **문제**: 2025년 임금체불 **2조 679억 원, 피해 노동자 26.2만 명**(노동포털 공식 통계, 신고사건 기준). 근로자는 카톡 대화·사진 근무표·명세서처럼 형식이 다른 증거만 갖고 있고, 상담사는 이를 날짜별로 맞추는 데 시간을 쓴다.
- **왜 AI인가**: 급여 계산은 규칙으로 된다. 어려운 건 "금요일 대신 토요일 나와줘" 같은 대화, 손글씨 근무표, 명세서 표를 읽고 **같은 근무 사건으로 연결**하는 일 — 양식이 제각각이라 파서로는 불가능하다.
- **AI 방식**: 문서 VLM 추출(날짜·시간·금액) → LLM이 증거 간 근무 사건 연결·모순 표시 → 사용자 확인 → **결정론적 Python 계산기**(시급·주휴·연장) → 원문 위치가 연결된 차이표 + 모국어 해설
- **데이터**: 자체 제작 근무표·대화·명세서(합성), 근로기준법은 국가법령정보 공동활용 API. 실제 개인 자료 사용 안 함.
- **하루 MVP**: 근로자 1명·1개월·문서 3종 → 타임라인 → 차이표 PDF. 정확도 지표: 근무시간 추출 정확도, 잘못 연결된 증거 수.
- **경쟁·차별**: **진정24**(증거 업로드→AI 사실 추출→진정서 PDF, 베타 무료)가 직접 경쟁. 진정24 공개 설명에 없는 **근무시간 타임라인 복원 + 계산식·가정·미확인 시간의 원문 연결 + 다국어**로 차별. 고용노동부 계산기·온라인 진정은 이미 있으므로 "계산 수단이 없다"는 문제 정의는 금지.
- **논문**: Westermann 2024 법률 서류 이미지 MLLM(2412.15260), LayoutLMv3(2204.08387), Donut(2111.15664)
- **리스크**: "체불 확정" 표현 금지(검토용 계산), 대화 상대 개인정보, 변호사법 — 상담사 검토 전제

## 2. [[L08-과업-기반-웹-접근성-재현|L08]] 과업 기반 웹 접근성 실패 재현·재검증 — 4.38
- **사용자**: 구청·대학·공공기관 웹 운영자와 개발사
- **문제**: 국내 웹 접근성 평균 **70.4점**(NIA 2025, 8개 업종 1,000개 사이트). 배경: 상위 100만 홈페이지 94.8%에 자동 검출 WCAG 위반(WebAIM 2025).
- **왜 AI인가**: 정적 검사(axe-core)는 "버튼 라벨 누락"은 찾지만 **"스크린리더 사용자가 실제로 예약을 끝낼 수 있는가"**는 못 본다. 과업을 이해하고 여러 단계를 수행하는 에이전트가 필요하다.
- **AI 방식**: 과업 입력("열람실 예약") → 화면 없이 **접근성 트리만 보는 에이전트**가 Playwright로 수행 + axe-core 병행 → 막힌 단계·키보드 경로·원인 요소 기록 → LLM 수정 패치 제안 → 같은 과업 재실행으로 Before/After
- **데이터**: 자체 제작 예약 사이트(오류 5개 의도 삽입), axe-core(MPL-2.0)
- **하루 MVP**: 사이트 1개·과업 3개. 실패 재현 → 패치 → 재검증 성공 화면.
- **경쟁·차별**: A11y Check(axe 기반 규칙 검사), WeBridge(GPT 링크 수정). **과업 단위 재현·재검증**은 공개 설명에서 미확인.
- **논문**: WebArena(2307.13854), ACCESS 접근성 위반 자동 수정(2401.16450), 시각장애인 대상 Computer-Use Agent 평가(2609.00524)
- **리스크**: 에이전트 실패 ≠ 접근성 실패(오탐). "접근성 인증"으로 표현 금지, 실제 장애인 사용성 평가를 대체하지 않음.

## 3. [[L09-지시어-연결-강의-자막|L09]] "여기 이 식" 지시어 연결 강의 자막 — 4.20
- **사용자**: 청각장애·난청 대학생, 장애학생지원센터
- **문제**: 자막은 "여기 값이 올라갑니다"를 받아 적을 뿐, **'여기'가 어느 그래프·수식인지**는 전달하지 못한다. 이공계 강의일수록 치명적. (국내 수강생 규모는 unknown, 배경: WHO 난청 재활 필요 4.3억 명)
- **왜 AI인가**: 음성·슬라이드·포인터 세 신호의 시간 정렬과 지시 대상 추론은 멀티모달 이해가 필요하다.
- **AI 방식**: STT(Whisper 계열) + 슬라이드 OCR/레이아웃 + 포인터 좌표 → 시간 동기화 → LLM이 지시어("이 식", "두 번째 항")와 영역 연결 → 해당 영역 강조된 자막 + 지시어가 실제 이름으로 치환된 복습 노트
- **데이터**: 팀이 직접 녹화한 3분 강의·슬라이드 5장(저작권 안전)
- **하루 MVP**: 녹화본 사후 처리. 자막 클릭 → 해당 수식으로 점프. 지시 대상 연결 정확도 측정.
- **경쟁·차별**: 소보로(문자통역), 에어사운드 Tkita(실시간 자막·다국어). 지시어-영역 연결은 공개 설명에서 미확인.
- **논문**: Multimodal Lecture Presentations Dataset(2208.08080), Whisper(2212.04356)
- **리스크**: 잘못된 영역 강조가 오히려 혼란 → 불확실하면 강조하지 않음

## 4. [[L01-전월세-서류-교차검증|L01]] 전월세 3종 서류 불일치 검토 — 4.18
- **사용자**: 관악·금천에서 첫 임대차 계약을 앞둔 청년, 주거상담사
- **문제**: 전세사기 **피해자등 누적 결정 41,559건**(국토부, 2026-09). 관악구 1인가구 비율 **63.5%**(스마트관악 2025-09). 주소 기반 위험조회는 이미 있지만(HUG 안심전세·세이프홈즈·관악구 주거정보 플랫폼), 계약서 특약·등기부·건축물대장의 **문구 간 불일치**는 사람이 직접 대조해야 한다.
- **왜 AI인가**: 등기부 갑구·을구 표, 취소선, 특약 문장은 양식이 제각각인 비정형 문서다. 문서 VLM이 필드와 원문 위치를 뽑아야 대조가 가능하다.
- **AI 방식**: 3종 서류 VLM 추출 → 소유자·주소·용도·근저당·특약 필드 대조(규칙) → 건축물대장 API·실거래가 API 도구호출 → 위험 신호 + 원문 하이라이트 + "중개사에게 요구할 특약 문구" 생성
- **데이터**: 건축물대장 API(건축HUB, 무료·제한 없음·자동승인), 국토부 전월세 실거래가 API. 등기부는 공식 API 미확인 → 가상 샘플.
- **하루 MVP**: 사기 유형별 가상 서류 세트 3개, 1개 법정동 실거래가, 불일치 규칙 5개
- **경쟁·차별**: SoftFlo EstateHub(AI 계약서 위험 문구), 세이프홈즈·집지켜(권리분석). "3종 동시 문구 대조 + 원문 위치"로 좁혀야 함. 단정적 우위 주장 금지.
- **논문**: ContraVis 계약서 모순 검토(2609.27014), CUAD(2103.06268), Westermann 2024(2412.15260)
- **리스크**: "안전한 계약" 판정 금지, 법률 자문 오인, 등기부 개인정보 비저장

## 5. [[L04-복지-청년정책-증빙-빈칸-찾기|L04]] 신청 전 증빙 프리체크 — 4.10
- **사용자**: 청년·복지 지원사업 신청자, 주민센터·사회복지 상담사
- **문제**: 정책 *추천*은 포화(온통청년 약 3,000개 정책·AI 챗봇, 복지로 복지멤버십). 남은 문제는 **신청 단계의 서류 누락·발급일 도과·요건 미확인으로 인한 보완 요청**. 배경: 한국 성인 31% 문해력 Level 1 이하(OECD 2024).
- **왜 AI인가**: 공고문의 자격 요건은 문장으로 쓰여 있고, 신청자 서류(등본·소득증명·임대차계약서)는 이미지다. 요건-증거를 연결하고 **추측하면 안 되는 빈칸을 질문**으로 바꾸는 일은 LLM이 필요하다.
- **AI 방식**: 공고문 RAG로 요건 구조화 → 서류 VLM 추출 → 요건별 충족/미충족/미확인 표 → 정보가 가장 부족한 항목부터 최소 질문(Uncertainty-aware) → 상담사 검토
- **데이터**: 중앙부처·지자체 복지서비스 API(무료·자동승인), 실제 공고 1건 + 합성 신청 서류
- **하루 MVP**: 실제 청년 지원사업 1개, 가구 사례 5개. 일부러 뺀 증빙을 찾아내는 장면.
- **경쟁·차별**: 추천이 아니라 "신청 직전 서류 점검". 동일 기능 국내 서비스는 확인 못 함(unknown).
- **논문**: Uncertainty of Thoughts(2402.03271), GPT-3 Statutory Reasoning(2302.06100), LLM+논리프로그램 세법 추론(2508.21051)
- **리스크**: 자격 확정 금지("확인 필요"로 표시), 소득·가족정보 민감

## 6. [[L13-소규모-사업장-작업-전-위험-점검|L13]] 작업 전 사진 1장 위험 표시 + 다국어 TBM 카드 — 3.93
- **사용자**: G밸리 소규모 제조·물류 현장 책임자, 외국인 작업자, 대학 실험실
- **문제**: 2024년 재해조사 대상 사고사망 **589명**(고용노동부).
- **왜 AI인가**: 같은 사진도 "통로 이동"인지 "사다리 작업"인지에 따라 위험이 다르다. 물체·사람·작업 의도의 관계를 해석해야 한다.
- **AI 방식**: 작업 설명 + 현장 사진 → VLM 위험 후보 위치 표시 → 작업별 점검 항목 매칭 → 다국어 음성 TBM 확인 카드 → 조치 후 재촬영 비교
- **데이터**: 허가된 공간에서 연출한 사진 20장, KOSHA 공개 지침
- **하루 MVP**: 위험 3종(통로 적치·바닥 케이블·사다리 주변)
- **경쟁·차별**: **세이프로(사진→체크리스트 자동작성)·AIR(AI 위험성평가서)** 직접 경쟁, KRAS. 서류 작성이 아니라 **작업 시작 5분 전 다국어 현장 확인**으로 좁혀야 함.
- **논문**: VLM 건설현장 위험 식별(2504.09083), LLM+VLM 위험 탐지(2511.15720)
- **리스크**: 사진 밖 위험 누락, "안전함" 판정 금지, 근로자 감시 전용

## 7. [[L05-화면-보고-알려주는-디지털-도우미|L05]] 화면 보고 다음 클릭을 알려주는 시니어 도우미 — 3.80
- **사용자**: 키오스크·공공웹 앞에서 막히는 고령자
- **문제**: 고령층 디지털정보화 역량 수준 **56.2**(일반국민=100, NIA 2026 발표)
- **왜 AI인가**: 화면은 사이트마다 다르고 계속 바뀐다. 현재 화면을 보고 "지금 어디를 눌러야 하는지" 판단하려면 GUI 그라운딩이 필요하다.
- **AI 방식**: 화면 캡처 → GUI 요소 파싱(OmniParser류) → 음성 질문 의도 이해 → 다음 클릭 위치 강조 + 음성 안내 → 클릭 후 화면으로 완료 여부 확인
- **데이터**: 모의 공공웹 2개(자체 제작)
- **하루 MVP**: 과업 3개(등본 발급 모의 등). L06과 결합하면 "고지서 읽기 → 납부 화면 안내" 한 흐름.
- **경쟁·차별**: 슈워요(음성 질문·큰 글씨 안내), 화면 인식 클릭 안내는 미확인
- **논문**: OmniParser(2408.00203), SeeClick(2401.10935), ElderBench(2609.04850)
- **리스크**: 실시간 오버레이 지연, 모의 화면과 실제 사이트 간극(Astra·Argon 공통 지적), 대리 조작은 하지 않음

## 8. [[L15-골목상권-점주-코파일럿|L15]] 상권 공공데이터 × 점주 매출 교차진단 — 3.80
- **사용자**: 관악 골목상권(샤로수길 등) 소상공인
- **문제**: 소상공인 주요 6대 업종 폐업률 **11.08%**(중기부, 2025)
- **왜 AI인가**: 상권 지표 요약은 이미 서울시 상권분석서비스가 챗봇까지 제공. 차별 지점은 **"매출 하락이 상권 탓인가, 내 메뉴 탓인가"를 분리**하는 분석 — 코드 실행 에이전트가 공공 시계열과 점주 데이터를 교차 분석해야 한다.
- **AI 방식**: 서울시 상권 추정매출(공공누리 1유형) + 점주 매출 CSV·배달 리뷰 → 데이터 분석 에이전트(코드 실행) → 원인 분리 리포트 + 행동 제안
- **데이터**: 서울 열린데이터광장 상권분석 데이터, 합성 점주 데이터
- **하루 MVP**: 3개 상권·2개 업종

## 9. [[L18-첫-오개념-진단|L18]] 오개념 가설 검증 교사 도구 — 3.78

- **문제**: 고2 수학 기초학력 미달 **12.6%**(2024 국가수준 학업성취도)
- **왜 AI인가**: 정답 비교로는 계산 실수와 개념 오해를 구분 못 한다. 손글씨 풀이에서 첫 오류를 찾고, **두 오개념 가설을 구별하는 문제**를 골라 학생 답으로 가설을 갱신해야 한다.
- **AI 방식**: 풀이 사진 → 줄별 수식 추출 → 기호 검산(SymPy) → 첫 불일치 → 오개념 가설 2개 → 구별 문제 → 응답으로 가설 갱신
- **데이터**: 자체 제작 일차방정식 오류 풀이 20개
- **경쟁·차별**: QANDA·매스플랫이 첨삭·오답 유형 리포트 상용화 → "가설 검증 루프"까지 가야 차별
- **논문**: 손글씨 수학 오류 MLLM 분석(2603.24961), Let's Verify Step by Step(2305.20050)
- **리스크**: 정당한 다른 풀이를 오답 처리, 학생 낙인
