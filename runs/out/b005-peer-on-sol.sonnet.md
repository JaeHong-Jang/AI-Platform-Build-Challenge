## 일정 현실성(5번 항목) 상세

빠지거나 과소평가된 작업은 다음과 같다.

1. **이미지 업로드 크기 문제.** 스마트폰 사진 여러 장은 원본이 수 MB다. 계획서는 "변환 이미지의 메타데이터 제거"만 언급하고, 클라이언트 리사이즈·압축은 일정에 없다. Vercel을 쓴다면 함수 요청 본문이 4.5 MB로 제한되고 초과 시 413이 발생한다(공식 문서에서 확인). 계획서는 배포 플랫폼을 정하지 않았지만 "09~10 배포"로 한 시간을 잡았으므로, 사진 3~5장과 견적서 2장을 서버로 보내려면 클라이언트 압축이나 직접 업로드를 반드시 일정에 넣어야 한다.
2. **HEIC 변환.** iPhone 사진이 HEIC로 올라올 때의 처리 방법이 일정에도 위험 표에도 없다(추정: Safari는 `accept="image/*"` 업로드 시 보통 JPEG로 변환하지만 보장하지 않으므로 실기기 테스트 항목에 넣어야 한다).
3. **마스킹 UI.** §6은 "얼굴·문서·주소를 가릴 수 있게" 하라고 하지만 P0 기능표와 당일 시간표에는 마스킹 화면 구현이 없다. 이 기능은 단독으로 반나절이 걸릴 수 있다.
4. **정답이 있는 평가 실행.** 16~17시에 "최종 평가 실행"이 들어 있는데, 평가 자동화 스크립트와 채점 UI는 준비 기간 작업으로 분리되어 있지 않다.
5. **프롬프트·스키마 반복.** 한국어 견적서 OCR 구조화는 첫 시도에 안정적으로 나오기 어렵다. 11시~12시에 "핵심 필드 수정 가능"까지 끝내는 것은 낙관적이다. 계획서가 "12시에 불안정하면 사용자 입력 경로로 후퇴"라고 적어 둔 점은 좋은 안전장치다.
6. **P0 기능 수.** P0만 6개(짐 목록, 견적 추출, 현장조건 질문, 대조 카드, 확인 문구, 당일 카드)이고 사용자 수정 UI가 각각 붙는다. 1인이 14시까지 완주하는 것은 비현실적이다(추정). 계획서의 "1인 P0만 구현" 항목이 가장 약하다. P0를 3~4개로 줄이는 대안이 1인 항목에 필요하다.
7. **발표·제출물.** 17~18시에 "제출 확인"이 있지만 본선 제출물 형식(발표자료·시연영상·소스)은 공식 안내 확인 전이다. 계획서가 이를 unknown으로 처리한 점은 정직하다.
8. **사전 구현 허용 여부가 unknown인데, 11/2~11/25 준비에 "API 후보 실험"이 포함된다.** 코드 작성 없이 API 호출만 해 보는 정도라면 문제없을 가능성이 높다(추정). 그러나 이를 근거로 당일 9시간 계획이 "처음부터 구현"이 되어 위 항목이 모두 당일 부담으로 들어온다.

## 계획서 전체 의견: 수정 필요(경미~중간)

사실 인용(약관 조항, 시행규칙, 분쟁해결기준, 논문 수치, API 기능, 경쟁사 설명)은 대부분 원문과 일치하고, 확인하지 못한 값을 unknown으로 남기고 "국내 최초"를 스스로 철회하는 등 정직성이 높다. 수정이 필요한 곳은 세 군데다.

1. **일정(§11).** 스마트폰 사진 압축·HEIC·마스킹 UI·업로드 한도 같은 빠진 작업을 시간표에 넣고, 1인 기준 P0를 3~4개 기능으로 줄인다.
2. **KCA 통계(§2, §13 ①).** 24.9%의 분모가 241이 아니라는 점(약 281, 원문 미설명)을 밝히거나, 24.9% 대신 70건이라는 절대 건수와 "피해 유형별 집계"라는 표현만 사용한다.
3. **약관 요약(§8).** 제5조 제3항 단서의 두 요건(고객 요청 변경 + 사전 고지)을 정확히 넣고, 제8조 제3항 "수고비"가 소비자분쟁해결기준 문구와 섞이지 않게 분리한다. 공정위 원본 PDF를 확보해 mowda.kr 전문이 최신 개정판인지 확인한다(공정위 목록의 등록일은 2014-10-01).

## 가장 위험한 주장 3개

1. **§11 "09~14시에 P0 6개 기능 완주"(1인 포함).** 업로드 압축·HEIC·마스킹·OCR 프롬프트 반복이 빠져 있어 본선 당일 실패로 이어질 가능성이 가장 높다(T1).
2. **§2, §13 ① 한국소비자원 "241건 … 추가비용 요구 70건·24.9%".** 241건과 24.9%의 분모가 서로 다른데(24.9%는 약 281건 기준) 같은 문단에 놓였다. 기획서 문장에 그대로 쓰이면 심사 과정에서 수치 오류로 보일 수 있다(L11).
3. **§9 성능 목표(짐 인식 85%, 필드 95%, 탐지 recall 90%, p95 60초)와 §8 약관 요약의 2차 출처 의존.** 목표치는 근거가 없고, 약관 조문은 사업자 전문에 의존한다. 허위는 아니지만 심사에서 "검증 완료"처럼 읽힐 위험이 있다(A8, L7).
