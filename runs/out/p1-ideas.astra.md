**추천 방향은 ‘AI가 증거를 읽고, 사람이 조치할 수 있는 결과물을 만드는 서비스’다.** 임금 누락 증빙, 접근 가능한 출입구 확인, 음식물 폐기 원인 파악처럼 사용 전후의 차이가 보이는 아이디어가 하루 해커톤에 적합하다.

아래 통계·논문·경쟁 서비스는 확인한 출처를 붙였다. 해외 통계는 문제의 배경이며 국내 시장 규모로 환산하지 않았다. **지불 의사·시장 공백·구현 가능성·점수는 모두 추정이고, 실제 고객 검증 결과는 `unknown`이다.** 경쟁사의 기능 부재를 단정하지 않고 우리가 집중할 범위를 차별점으로 제시한다.

MVP는 **추정: 2~3인, 기존 모델 추론 활용, 신규 모델 학습 없이 9시간**을 기준으로 잡았다. 제시한 샘플 수는 확보된 데이터 수가 아니라 준비·검증 목표다. 이용 조건이 `unknown`인 외부 자료는 허가 확인 전까지 MVP에 넣지 않고 자체 제작 자료로 대체한다. 논문은 접근법의 근거이며 제안 서비스의 성능을 보증하지 않는다.

### 1. 일한만큼 — 흩어진 근무 증거를 연결해 임금 누락 의심 구간을 찾는다

- **주요 사용자**: 근무표가 자주 바뀌는 아르바이트생, 단기근로자, 대학 노동상담 담당자. **추정: 지불 주체**는 대학·노동권익센터·노무법인이다. 상담 전 자료 정리 시간을 줄이는 기관용 도구로 판매한다.
- **문제**: 2024년 국내 임금체불액은 **2조 448억 원**, 피해 노동자는 약 **28.3만 명**이었다. 이 통계 전체를 서비스로 해결할 수 있다는 의미는 아니다. [고용노동부 임금체불 통계](https://labor.moel.go.kr/arrstat/arrstat_list.do?edScleYear=2024&edToidYear=2024&edYrYear=2024&stScleYear=2022&stToidYear=2020&stYrYear=2020&tabArea=tab04)
- **왜 AI여야 하나**: 급여 계산 자체는 규칙으로 가능하다. 핵심은 “금요일 대신 토요일 출근” 같은 대화, 사진 근무표, 급여명세서를 읽어 **실제 근무 사건과 모순을 복원**하는 것이다. 고정 양식 파서만으로는 다양한 표현을 처리하기 어렵다.
- **AI 적용 방식**: 문서 OCR/VLM → 날짜·시간·수당 항목 구조화 → 문서 간 사건 연결 → 사용자 확인 → 결정론적 급여 계산 → 원문 위치가 연결된 차이표.
- **데이터/API**: 자체 제작 근무표·대화·명세서 사용, 외부 URL·라이선스는 해당 없음. 제도 확인은 [고용노동부 노동포털](https://labor.moel.go.kr/), 원문 열람 방식이며 안내문 재배포 조건은 `unknown`. 실제 사용자 자료는 명시적 동의를 받아 처리한다.
- **핵심 기능 3개 & 이용 흐름**: ① 근무 타임라인 복원 ② 증거 간 불일치 표시 ③ 상담용 증빙 묶음 생성. 자료 업로드 → 애매한 근무 확인 → 누락 의심 날짜 선택 → 원문과 계산 근거 내려받기.
- **하루 해커톤 MVP 범위**: 근로자 1명·1개월·문서 3종. 약정 시급과 확인된 근무시간 대비 지급액 차이만 계산한다. 복잡한 수당·퇴직금 판단은 제외하고, 시간 추출 정확도와 원문 연결 정확도를 측정한다.
- **경쟁·유사 서비스와 차별점**: [Newploy](https://www.newploy.net/)는 근태·급여 업무 자동화를 제공한다. **추정: 차별점**은 사업주의 정형 근태자료가 없는 상황에서 근로자 보유 증거를 역으로 연결하는 기능이다.
- **관련 논문/근거**: *LayoutLMv3: Pre-training for Document AI with Unified Text and Image Masking* (2022), [arXiv:2204.08387](https://arxiv.org/abs/2204.08387).
- **리스크**: 대화 상대 개인정보, 휴게시간 오인, 문서 위조, 법률 판단으로의 과도한 확장. 결과는 ‘체불 확정’이 아닌 ‘확인할 차이’로 제시하고 상담자가 검토한다.
- **자체 점수(추정, 1~5)**: 문제심각도 **5** / AI필연성 **4** / 구현가능성 **5** / 데이터확보 **5** / 차별성 **4** / 시연임팩트 **5**

### 2. 복지빈칸 — 복지 신청에 필요한 증거와 아직 확인되지 않은 사실을 찾아준다

- **데이터/API**: [한국사회보장정보원 중앙부처복지서비스 API](https://www.data.go.kr/data/15090532/openapi.do), 활용신청·서비스키 방식. 세부 이용허락 조건과 승인 소요시간은 `unknown`. MVP는 자체 제작 가상 지원사업 3개와 합성 서류를 사용하고 실제 제도 적용은 별도 검증한다.
- **핵심 기능 3개 & 이용 흐름**: ① 요건별 증빙 연결 ② 빠진 정보에 대한 최소 질문 ③ 신청 준비 목록 생성. 상황 설명 → 서류 등록 → 미확인 항목 답변 → 담당자 검토용 목록 완성.
- **하루 해커톤 MVP 범위**: 가상 제도 3개·가구 사례 5개·서류 유형 3개. 자격 확정 없이 ‘자료로 확인됨/추가 확인 필요’를 구분하고, 일부러 뺀 증빙을 찾아내는 장면을 시연한다.

- **관련 논문/근거**: *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks* (2020), [arXiv:2005.11401](https://arxiv.org/abs/2005.11401).
- **리스크**: 소득·건강·가족정보 노출, 정책 개정, 누락된 증거를 부적격으로 오인하는 문제. ‘모름’을 유지하고 담당자 판단을 지원해야 한다.
- **자체 점수(추정, 1~5)**: 문제심각도 **5** / AI필연성 **4** / 구현가능성 **4** / 데이터확보 **3** / 차별성 **4** / 시연임팩트 **4**

### 3. 마지막50m — 휠체어가 목적지 입구까지 도달할 수 있는지 사진으로 확인한다

- **핵심 기능 3개 & 이용 흐름**: ① 출입구 장애요소 표시 ② 이용자 조건별 대체 입구 제안 ③ 새 사진으로 상태 갱신. 목적지 선택 → 휠체어 조건 입력 → 근거 사진 확인 → 가능한 입구 선택.
- **하루 해커톤 MVP 범위**: 캠퍼스 건물 3개·입구 10개·고정 경로망. 사진만으로 문턱 높이를 추정하지 않고 실측값을 사용한다. 장애물 사진을 추가했을 때 추천 입구가 바뀌는 장면을 시연한다.
- **경쟁·유사 서비스와 차별점**: [Wheelmap](https://wheelmap.org/)은 휠체어 접근 가능한 장소를 찾는 서비스다. **추정: 차별점**은 건물 단위 평가보다 출입구별 최신 증거와 임시 장애물에 집중하는 것이다.
- **관련 논문/근거**: *Visual Instruction Tuning* (2023), [arXiv:2304.08485](https://arxiv.org/abs/2304.08485); *Segment Anything* (2023), [arXiv:2304.02643](https://arxiv.org/abs/2304.02643).
- **리스크**: 오래된 사진, 사진 밖 장애물, 사용자별 이동능력 차이, 안전한 경로라는 과신. 촬영 시각·미확인 구간·실측 여부를 표시한다.

### 4. 약겹침 — 약봉투·포장·복약표에서 서로 맞지 않는 항목을 찾아 약사에게 연결한다

- **핵심 기능 3개 & 이용 흐름**: ① 복약 목록 자동 작성 ② 같은 품목의 중복·지시 차이 표시 ③ 약사에게 물어볼 항목 생성. 촬영 → 품목 확인 → 차이 검토 → 약사 확인.
- **하루 해커톤 MVP 범위**: 품목 10개 이내·가상 환자 3명. 식별·문서 대조만 구현하고 상호작용 진단, 용량 변경, 복용 중단 추천은 제외한다.
- **경쟁·유사 서비스와 차별점**: [Medisafe](https://medisafe.com/)는 복약 관리와 환자 지원 서비스를 제공한다. **추정: 차별점**은 여러 출처의 종이 문서를 맞춰보는 ‘복약 목록 확인’ 순간에 집중하는 것이다.
- **관련 논문/근거**: *LayoutLMv3: Pre-training for Document AI with Unified Text and Image Masking* (2022), [arXiv:2204.08387](https://arxiv.org/abs/2204.08387).
- **리스크**: 약명·함량 오독, 민감정보, 의료적 판단으로 오인. 불확실한 약은 자동 확정하지 않고 약사의 최종 확인을 전제로 한다.

- **데이터/API**: 직접 촬영한 포장재와 해당 시설이 사용을 허락한 배출 기준. 보조 후보인 [TACO](https://github.com/pedropro/TACO)는 다운로드 도구를 제공하지만 저장소 코드 라이선스와 이미지 사용 조건을 구분해야 한다. 원본 이미지별 사용 조건은 이번 확인에서 `unknown`이므로 MVP는 자체 사진을 쓴다.
- **핵심 기능 3개 & 이용 흐름**: ① 부위별 인식 ② 재질·오염 불확실성 질문 ③ 현장 분리 순서 안내. 사진 촬영 → 표시 부분 추가 촬영 → 부품 분리 → 수거함 선택.

### 14. 방상태기록 — 입주·거주 중 사진을 정렬해 누수·변색 등 변화의 증거를 남긴다

- **주요 사용자**: 자취 대학생, 기숙사 운영자, 임대주택 유지보수 담당자. **추정: 지불 주체**는 기숙사·주택관리업체이며, 수선 접수의 재촬영·현장 확인 횟수를 줄이는 도구로 판매한다.
- **문제**: WHO의 2009년 실내공기질 지침은 부유한 국가의 주택 습기 문제 유병률을 보고 방식에 따라 **약 10~50%** 범위로 설명했다. 오래되고 범위가 넓은 해외 자료이며, 국내 자취방 발생률은 `unknown`이다. [WHO 지침, NCBI 원문](https://www.ncbi.nlm.nih.gov/books/NBK143945/)
- **왜 AI여야 하나**: 단순 사진 보관은 조명·각도가 달라지면 비교가 어렵다. AI가 **같은 위치를 대응시키고 변화 후보 영역을 찾아 추가 촬영**을 안내한다.
- **AI 적용 방식**: 이전·현재 사진 → 시각적 위치 정렬 → 변화 영역 탐지 → 누수 흔적·변색 등 후보 분류 → 추가 관찰 요청 → 수선 접수 기록.
- **데이터/API**: 촬영 권한이 있는 방·모형 벽면의 자체 사진. 외부 데이터 URL·라이선스는 해당 없음. WHO 문서는 문제 근거로 인용하며 이미지 학습자료로 사용하지 않는다.
- **핵심 기능 3개 & 이용 흐름**: ① 동일 구도 재촬영 안내 ② 변화 영역 강조 ③ 시점별 수선 요청 기록. 입주 사진 저장 → 현재 사진 촬영 → 변화 확인 → 담당자 검토용 묶음 생성.
- **하루 해커톤 MVP 범위**: 벽·창틀·천장 3개 부위, 사진 쌍 15개. 젖음·변색·표면 손상 후보만 다루고 원인·책임·수선비는 판정하지 않는다.
- **경쟁·유사 서비스와 차별점**: [RentCheck](https://www.getrentcheck.com/)는 거주자 주도 점검·사진·보고서를 제공한다. **추정: 차별점**은 한국 대학생 주거의 반복 촬영과 변화 위치 비교에 집중하는 것이다. 경쟁사 AI 기능과의 세부 중복은 추가 확인이 필요하다.

### 15. 여기자막 — 강사의 ‘여기·이 식’이라는 말을 슬라이드의 실제 위치와 연결한다

- **주요 사용자**: 청각장애·난청 대학생, 장애학생지원센터, 교육 콘텐츠 제작자. **추정: 지불 주체**는 대학·교육기관이며, 전문과목 학습 접근성 개선에 활용한다.
- **문제**: WHO는 전 세계 **약 4억 3천만 명**이 장애성 난청에 대한 재활 서비스를 필요로 한다고 설명한다. 이 수치가 자막 사용 대학생 수를 의미하지는 않는다. [WHO, Deafness and hearing loss](https://www.who.int/en/news-room/fact-sheets/detail/deafness-and-hearing-loss)
- **왜 AI여야 하나**: “여기 값이 올라갑니다”라는 자막만으로는 가리키는 그래프를 알 수 없다. **음성·슬라이드·포인터의 시점을 맞춰 지시 대상과 전문용어를 연결**해야 한다.
- **AI 적용 방식**: 음성 STT+슬라이드 OCR → 시간 동기화 → 전문용어 후보 보정 → 지시어와 도표·수식 영역 연결 → 위치가 표시된 자막.
- **데이터/API**: 팀원이 직접 제작한 슬라이드와 동의받아 녹화한 강의. 외부 데이터 URL·라이선스는 해당 없음. 타인의 강의 영상·유료 교재는 사용하지 않는다.
- **핵심 기능 3개 & 이용 흐름**: ① 용어 근거가 연결된 자막 ② ‘여기’의 대상 영역 강조 ③ 놓친 구간의 음성·슬라이드 동시 재생. 강의 재생 → 자막·강조 확인 → 특정 문장 선택 → 해당 장면 복귀.
- **하루 해커톤 MVP 범위**: 3분 강의·슬라이드 5장·포인터 기록이 있는 녹화본. 실시간 전체 강의 대신 녹화 영상으로 시연하고 지시 대상 연결 정확도를 측정한다.
- **경쟁·유사 서비스와 차별점**: [Ava](https://www.ava.me/)는 청각장애·난청 사용자를 위한 자막 서비스를 제공한다. **추정: 차별점**은 STEM 강의에서 말과 도표·수식의 공간적 관계를 복원하는 것이다.
- **관련 논문/근거**: *Robust Speech Recognition via Large-Scale Weak Supervision* (2022), [arXiv:2212.04356](https://arxiv.org/abs/2212.04356); *Visual Instruction Tuning* (2023), [arXiv:2304.08485](https://arxiv.org/abs/2304.08485).
- **리스크**: 전문용어를 잘못 보정해 의미를 바꾸는 문제, 대상 영역 오인, 지연, 강의 저작권. 원래 인식 결과와 보정 내용을 구분하고 불확실한 연결은 표시하지 않는다.
- **자체 점수(추정, 1~5)**: 문제심각도 **4** / AI필연성 **5** / 구현가능성 **4** / 데이터확보 **5** / 차별성 **4** / 시연임팩트 **5**
