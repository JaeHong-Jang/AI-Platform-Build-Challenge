| 85~120초 | ‘책장 포함 여부 미확인’, ‘계단 비용 조건 불명확’ 두 카드 제시 | 사진·원문·조건이 연결되는 핵심 가치 |
| 120~150초 | 두 항목을 확인 요청으로 변환하고 복사 | 사용자가 취할 다음 행동 |
| 150~175초 | **가상 업체 답변** 제시: 책장은 포함, 계단 비용은 미답변 | 미답변을 합의로 처리하지 않음 |
| 175~180초 | “계약금 보내기 전에, 무엇을 확인해야 하는지 구체화합니다.” | 제품의 약속 |

가상 답변 첨부 기능이 P1이면 마지막 장면은 **설명용 화면**으로 명시합니다. API 지연으로 사전 실행 결과를 보여줄 때도 표시해야 합니다. 수동입력으로 흐름을 이어가는 것은 유효한 오류 대응이지만, 실시간 AI 분석 성공의 증거로 제시해서는 안 됩니다.

“주 사용자는 비대면 견적을 받고 계약금을 보내려는 청년입니다. 실제 지불 의사는 unknown입니다. 추정: 초기에는 청년 지원 채널을 통한 이용자 모집과 사용성 검증이 가능할 수 있습니다. 기관 제휴나 유료화를 확정 사업모델로 제시하지 않고, 확인 요청 완료율·업체 답변률·사용 의사를 먼저 확인하겠습니다.”

**6. 다른 지휘부 멤버와 의견이 갈릴 것 같은 주장**

- **R5·R10 — 당일 카드의 P0 포함 여부:** 기술 관점에서는 기존 결과를 재사용하면 구현 부담이 작다고 볼 수 있습니다. 저는 별도 당일 대응 기능은 P1로 두고, P0에는 근거가 연결된 결과 화면만 남기는 편을 권고합니다.
- **R7 — 약관 규칙의 개수와 출력 강도:** 기술 관점에서는 다수 규칙의 코드화를 가능하다고 볼 수 있습니다. 저는 규칙 수보다 적용조건·예외의 정확성이 중요하며, 확인 질문 중심의 소수 규칙만 공개하는 편을 권고합니다.
- **R6·R12 — 차별점과 사업성의 충분성:** 기술적으로 외부 문서 대조를 구현해도 고객 획득과 지불 의사가 입증되지는 않습니다. 저는 **예선 기획 방향으로는 찬성하지만, 독점적 차별성과 사업성 검증 완료 주장은 보류**합니다.
