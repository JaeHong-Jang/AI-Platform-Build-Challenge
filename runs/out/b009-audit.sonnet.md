## 1. 화면별 기능 지도

범례: 있음 / **빠짐**(목적상 필요한데 없음) / **겹침**(다른 화면과 중복·섞임)

### 1-1 시작 (`StartView`) — 목적: 입력 0개로 맞춤 홈을 만들 조건 받기
- 있음: 한 줄 문장 + 조건 해석관(LLM), 예시 문장, 칩(집 유형·출발/도착 엘베), 칩으로 시작, 가상 사례로 해 보기.
- 빠짐: 출발/도착 **층수 칩**(문장으로만 가능, 칩에는 엘베만 있음 — 문장을 못 쓰는 사용자는 층을 못 넣고 시작 후 '짐·조건'에서 고쳐야 함), 짐 선택(칩으로 시작하면 짐 0개), 구(관악구) 선택(`Intake.gu` 필드는 있는데 UI 없음 → 허가 목록 대조가 구 정보 없이 동작), 이사 희망 날짜, 이전 기록 이어하기(세션 저장소라 탭을 닫으면 사라지는데 이를 알리는 문구 없음).
- 겹침: **데모('가상 사례로 해 보기')가 실사용 시작 버튼과 같은 줄·같은 위계**. 데모는 곧바로 `#/quotes`로 보내고 홈이 아니라서, 사용자가 의도한 "시작→홈" 흐름과 다르다.

### 1-2 홈 (`HomeView`) — 목적: "지금 뭘 해야 하나" 한 가지 + 점검 상황 요약
- 있음: 지금 할 일 1개, KPI 4개, 이삿짐 장면(3패널 + 에이전트 줄), 탭(산정표·물을 질문·서류), 건너뛰기.
- 빠짐: 에이전트가 **무엇을 했고 결과가 무엇인지**(역할별 산출물 한 줄) — 현재는 이름·상태·LLM/규칙 칩만 있고 산출물이 없다. 이것이 "대기만 뜬다"의 UX 쪽 원인(4절). 장면에서 선택한 상자의 **상세/근거로 이동 링크**(근거 그래프로 가는 링크가 홈 어디에도 없음). 다음 단계 진행 표시(1·2·3단계 중 어디).
- 겹침: ① 산정표 탭 = 견적·업체의 '대조표'와 같은 카드 목록(간략판) ② 물을 질문 탭 = 견적·업체의 업체 문의 패널 ① ③ 서류 탭 = 계약·서류 화면 ④ KPI '받은 서류 0/2' = 계약·서류. 홈이 요약이 아니라 **세 화면의 축소 복제**가 되어, 같은 항목을 3곳에서 보게 된다.

### 1-3 짐·조건 (`ItemsView`) — 목적: 옮길 짐과 현장 조건 확인
- 있음: 짐 표(이름·분류·수량 ±·옮김 체크·삭제), 후보 불러오기, 빠른 추가 칩, 직접 적기, 출발/도착 층·엘베·주차 거리, 사다리차 필요, "아직 모르는 것" 경고.
- 빠짐: **일괄 선택/해제**(8개를 각각 체크), 수량 직접 입력(± 클릭만; 박스 6개는 5번 클릭), 변경 취소, 짐 사진·부피 메모(의도적 제외라면 문구로 안내).
- 겹침: 시작 화면의 칩(집 유형·엘베)과 같은 정보를 여기서도 입력 — 입력점이 둘.

### 1-4 견적·업체 (`QuotesView` + `InquiryPanel`) — 목적: 견적 붙여넣기 → 읽기 → 대조 → 업체에 물을 것 → 답변 점검 → 업체 선택
- 있음: 견적 탭(A/B/추가), 나란히 비교표, 견적 원문 + 항목 읽기, 읽은 항목 고치기, 대조표(필터 5), 선택 행 근거, 업체 문의(문장 작성·복사·보냈다고 기록), 답변 점검(에이전트), 반영 승인, 이 견적으로 진행.
- 빠짐: **견적 삭제 확인/되돌리기**(휴지통 아이콘 1번), 비교표에서 **원하는 항목만 고정**, 답변 반영 후 되돌리기(승인 취소 UI 없음), 보낸 시각/업체 연락처 기록, 문의 문장 **카카오톡용 짧은 버전**.
- 겹침: ① **계약금 14% 경고가 비교표(여기)와 계약·서류 화면 양쪽에 따로 나온다** ② 문의(1)와 답변 점검(2)이 한 패널에 섞여 있고 에이전트가 "점검"과 "반영"까지 한 흐름 → 단계가 많음 ③ 업체 선택(`고르기` 행)이 비교표 맨 아래.

### 1-5 계약·서류 (`ContractView`) — 목적: 계약금 보내기 전 서류 기재 항목·계약금 비율 점검
- 있음: 받을 서류 체크리스트(견적서 제4조, 계약서 제5조), 견적서 글에서 항목 자동 대조('글에 있음/못 찾음'), 계약서 글 붙여넣기, 계약금 10% 비율 점검.
- 빠짐: 계약서 글을 넣기 전에는 계약서 항목이 모두 "—"라 **왜 비어 있는지 안내가 없음**(A/1440-light-06-contract.png 좌하단), 계약서 항목별 자동 대조 결과(붙여넣으면 나오는지는 미확인 — 글 없이 캡처), 선택한 업체(`chosen`) 표시가 이 화면에 없음(헤더만 '견적 A').
- 겹침: 계약금 비율 점검이 견적·업체 비교표에도 있음(위). 서류 체크박스는 홈 KPI·홈 서류 탭과 같은 상태.

### 1-6 근거 그래프 (`GraphView`) — 목적: 카드 하나가 어디서 나왔는지 추적
- 있음: 확인 항목 목록(남은 것만 토글), 4열 사슬(내 입력→확인 항목→근거→참고 조항·물을 것), 온톨로지 표.
- 빠짐: **연결선/화살표**(데스크톱에서 `.chain-rel`이 `display:none`이라 열 사이 관계 표현 없음), 항목 → 견적·업체로 **되돌아가는 링크**. 그래프라기보다 4열 카드 배열.
- 겹침: 견적·업체의 '선택한 행의 근거' 패널과 같은 정보(같은 카드의 원문·참고 조항·질문)를 다른 레이아웃으로 반복.

### 1-7 참고 조항·통계 (`RefsView`) — 목적: 앱이 쓰는 법령·통계 출처 공개
- 있음: 통계 3개(출처 표기), 소비자원 권고 인용, 표준약관 조항 6개와 '설명' 링크.
- 빠짐: 어느 확인 항목이 어느 조항을 쓰는지 **역방향 링크**, 통계 기준일 한눈에(각 카드 foot에만).
- 겹침: 조항 문구가 견적·업체 '참고 조항'과 근거 그래프 4열에 중복 출력.

### 1-8 실행 기록 (`LogView`) — 목적: 에이전트가 한 일 감사 로그
- 있음: 답변 점검 에이전트 호출 기록(도구·수락/거절 이유). 비어 있을 때 빈 화면 안내(A/1440-light-09-log.png).
- 빠짐: **제목은 "에이전트 기록"인데 10명 중 1명(답변 점검관)만 기록** — 문서 읽기관 4.4초 호출, 조건 해석관 호출은 안 남음(`state.quotes.flatMap(x => x.runs)`가 replycheck 전용). 시간순 필터·내보내기 없음.
- 겹침: 홈의 에이전트 줄이 보여야 할 "무슨 일을 했나"를 이 화면이 가져가 있음 → 홈은 대기만, 기록은 한 명뿐.

### 1-9 레일 (`Dashboard` aside.rail) — 목적: 이동 + 에이전트 켜기/끄기
- 있음: 로고, 새 이사 시작, 이사 4메뉴(개수 배지), 에이전트 10명 토글(상태 점), 근거·기록 3메뉴, 면책 문구.
- 빠짐: **현재 진행 단계 표시**(1 시작 → 2 홈 → …), 에이전트 토글의 **효과 미리보기**(title 툴팁에만 `끄면:` 있음 — 터치 불가).
- 겹침: **에이전트 토글이 레일·장면 에이전트 줄 두 곳에 있음**. 레일 점은 "켜짐(주황 '대기')/작동(초록)"인데 장면 줄은 다른 문구 체계 — 같은 에이전트가 두 표기.

### 3-1 클릭 수·흐름

### 3-2 뜻이 불분명한 문구
- **"대기"**(에이전트 상태): 쉬는 중인지, 내가 뭘 해 주길 기다리는지, 끝났는지 알 수 없다. 규칙 에이전트는 이미 계산이 끝나 있는데 "대기"로 표시(4절).
- "입력 없음": 계약 점검관·답변 점검관 카드에 점선만 — 무엇을 넣어야 하는지(계약서 글, 업체 답변) 안 알려 줌.
- "원문에 없어 버린 값 2개: 사다리차: '별도' …" — **"버린 값"**이 사용자에게 무슨 의미인지(AI가 만든 값을 앱이 지웠다는 뜻) 설명 없음(1440-light-02-quotes).
- "확인 완료 5/13" — 13개 중 5개가 '명시됨'이라는 뜻인데 "완료"라 하면 **내가 할 일을 5개 끝냈다**로 읽힘(실제로는 업체가 적어 줬다는 뜻). 진행 막대가 초록으로 차오르면서 오해.
- "공개 전 대기 4" / "공개된 카드 4장" — 시스템 연출 용어. 사용자는 "공개"를 한 적이 없다.
- 장면 "멈춤선 — 확인될 때까지 여기서 대기" — 은유가 설명 없이 문장 하나로 나옴.
- "온톨로지" 표(근거 그래프 하단): `references.ts` 같은 **파일명이 사용자 화면**에 노출.
- '고르기' 행 "이 견적으로 진행" — 진행하면 무엇이 달라지는지(홈 안내가 계약으로 넘어가는 것뿐) 없음.
- 상태 4종(명시됨·포함 여부 미확인·조건 모호·판독 불가)의 **차이**를 설명하는 범례가 어느 화면에도 없음(기호만).

## 4. "대기만 뜨고 동작이 안 된다" — 원인 (코드)

### 4-1 서버가 서빙한 빌드(옛 HomeView, 사용자가 본 것)
실측 `afterStates` = 8x "대기" + 2x "입력 없음", 레일 점 = 지휘관만 초록, 나머지 9개 **주황(wait)**, 작동 중 0.

`lib/agents.ts`
```
agentState(id, on, busy, hasInput):
  꺼짐 → 입력 없음(hasInput=false) → busy.includes(id) ? "작동 중" : "대기"
```
→ **"작동 중"이 되는 유일한 조건은 `busy` 배열에 id가 들어 있을 때**. "완료" 상태는 없다. 일이 끝난 에이전트의 기본값이 "대기"다.

`HomeView.tsx`(옛):
```
const run = busy.includes(a.id) || (playing && (matcher|asker|conductor));
hasInput = picker:견적>1 / replycheck:답변 있음 / contract:선택·계약글 / reader:견적>0 / 그 외 true
```
작동 중이 되는 경우는 딱 두 가지:
1. **`busy`**: `Dashboard.working(id,true)`가 불릴 때만. 호출처는 두 곳 — `readQuote()`의 `working("reader")`, StartView의 `onBusy → working("intake")`. 즉 **LLM 2명(문서 읽기관·조건 해석관)** 뿐.
   - 문서 읽기관은 가상 사례 직후 **견적·업체 화면에서** 도는데(`loadSample`이 `location.hash="#/quotes"`), 사용자는 거기서 홈을 안 보므로 홈의 '작동 중'을 못 본다. 홈으로 가면 이미 끝나 있다.
   - 조건 해석관은 **시작 화면에서만** 도는데 그때 홈은 아직 열리지 않는다(`started=false`).
   - **답변 점검관(LLM)**: `InquiryPanel.review()`가 `agentPost("replycheck")`만 하고 **`working("replycheck")`를 호출하지 않음** → 12.4초 동안도 레일·장면·상단 pill("작업 중 N")에 '작동 중'이 **안 뜬다**. (grep 결과 `working(` 호출은 reader/intake뿐.)
2. **`playing`(공개 연출 중)**: `useReveal`이 도는 동안 `matcher·asker·conductor` 3명만 '작동 중'. 실측: 홈 진입 후 12.0초간 3명, 끝나면 0. 그나마 ① 세션당 **첫 방문에만**(`isa-seen` sessionStorage — 이후엔 `seen`이라 즉시 전부 공개, `playing`=false) ② 문의 작성관은 대조관과 **동시에** 작동 중(순서 없음)이라 "읽기관 대기 → 대조관·문의 작성관 작동" 식으로 앞뒤가 안 맞고 ③ `animating()`은 작동 중 앞 4명만 움직임.

그 결과 사용자가 **정상 흐름(데모→견적 화면→홈)** 에서 홈에 오면: 이미 연출을 안 보고 왔으니 첫 방문이면 12초 연출이 돌고(3명 작동), 건너뛰거나 이후에 오면 **전원 "대기"**.

**규칙 에이전트 7명은 구조적으로 '작동 중'이 될 수 없다**: `rules.compare()` 등은 순수 함수를 `useMemo`로 **즉시** 계산해 결과가 이미 화면에 있고(0ms), 상태 머신에는 '일하는 구간'이 존재하지 않는다. 화면은 일이 끝난 결과(상자·칩)와 "대기"를 동시에 보여 주므로 **모순**.

`scene/*`:
- `AgentStrip.STATE_MARK`: `대기: "‖"`(일시정지 기호). 일시정지로 읽힘.
- `Stage.stateOf(id)`: `agents.find(...)?.state ?? "대기"` — 기본값 "대기".
- `Figure`: `anim`이 `animating()`(작동 중 앞 4명)일 때만 움직임 → 대기 캐릭터는 정지 사진.
- `scene.ts`: 상자 이동은 `revealed` 커서만 따름 → 캐릭터와 연결 없음.

레일(`Dashboard.tsx`): `adot ${busy ? "on" : "wait"}` — 켜진 에이전트는 **전부 주황 '대기' 점**이 기본.

### 4-2 사용자 입장 요약(왜 대기만 보이나)
1. 일하는 구간이 없다 — 규칙 에이전트는 즉시 끝난 상태를 "대기"로 표시한다.
2. '작동 중'은 ① LLM 호출 중(그것도 reader·intake만, 홈 밖에서) ② 첫 방문 12초 연출 중 3명뿐.
3. 답변 점검관 LLM은 `working()` 미호출로 12초 작동해도 표시 안 됨.
4. 끝난 일을 보여 주는 "완료"+산출물 한 줄이 없다.
5. 연출 12초는 느리고 "작동 중"이 3명 동시라 순서·인과가 안 보인다.

### 4-3 새 작업 트리(16:47~16:49 수정분)에서의 해결 여부 — 코드만 읽음, **서빙되지 않아 실행 검증 못 함**
- `AgentState`에 `"완료"` 추가, `lib/pipeline.ts`의 `ORDER`/`reports()`(에이전트별 `outcome`·`output`), `HomeView.usePlayback`이 **지휘 순서대로 에이전트 1명씩 380ms '작동 중 → 완료'**, 대조관만 `n x 90ms`(13장 ≈1.2초), 전체 약 4~5초. 이 방향이면 4-1의 1·4·5번이 해결된다.
- **여전히 남을 항목(확인 필요)**: ① `busy.includes(a.id)`가 playing보다 우선 — `InquiryPanel`이 `working("replycheck")`를 부르는지(현재 안 부름) ② 세션 첫 방문 이후 재생 생략(`isa-seen`)이면 사용자는 "완료" 상태만 보게 됨(이건 의도적으로 OK) ③ 모바일은 장면이 3단 적층이라 재생을 못 봄.
