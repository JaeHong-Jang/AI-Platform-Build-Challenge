# AI Platform Build Challenge 예선 기획 — 기술 프런티어 관점 아이디어 15선 (지휘부: Gemini 4 Argon)

본 문서는 **서울특별시·관악구·금천청년꿈터·서울대학교 앵커사업단**이 주최하고 **데이콘(DACON)**이 운영하는 「AI Platform Build Challenge」의 특성을 반영하여, **2024~2026년 최신 AI 기술 패러다임(OCR-free Document VLM, Full-Duplex Speech-to-Speech, Pure-Vision GUI Agent, GraphRAG, On-Device SLM, Spatial VLM, Spatiotemporal Video VLM, Synthetic Persona 등)**이 사상 처음으로 해결 가능하게 만든 **15개 서비스·플랫폼 아이디어**를 정리한 결과입니다. 모든 아이디어는 대학생 1~3인이 **11월 27일(09:00~18:00, 9시간) 하루 해커톤**에서 실제로 구현·시연 가능한 MVP 아키텍처를 기준으로 설계되었습니다.

### 1. 권리가드 VLM (KwolliGuard VLM) — 다중 부동산 공적장부 시각 교차검증 및 권리관계 그래프 추론 전세사기 방어 플랫폼
- **주요 사용자**: 서울 관악구(신림·봉천동)·금천구(가산·독산동) 등 비아파트(다세대·연립·다가구) 밀집 지역에서 전·월세 계약을 앞둔 20~30대 대학생 및 사회초년생 1인가구.
- **문제**: 국토교통부 《전세사기피해자 지원 및 주거안정에 관한 특별법》 가결 및 서울시 집계에 따르면, 서울시 전세사기 접수 건수는 2023년 2,502건, 2024년 4,198건, 2025년 3,304건에 달하며, 이 중 **관악구가 2025년 단일 연도 801건(누적 피해주택 1,300여 가구 이상)으로 서울시 25개 자치구 중 1위**를 기록하고 있다(금천구 299건 등 청년 밀집지 집중) (출처: 서울열린데이터광장 `서울특별시 자치구별 전세사기 발생건수` https://data.seoul.go.kr , 국토교통부 https://www.molit.go.kr ). 또한 관악구는 전체 가구 중 1인가구 비율이 약 63.5%~63.8%(KOSIS 등록센서스 기준 약 62% 이상)로 전국 최고 수준이어서 부동산 거래 경험이 부족한 청년층 피해가 극심하다 (출처: 국가통계포털 KOSIS https://kosis.kr , 관악구청 https://www.gwanak.go.kr ).
- **왜 AI여야 하나**: 기존 규칙 기반 서비스나 단순 OCR은 등기부등본(갑구·을구의 취소선·말소사항·공동담보 목록), 건축물대장(쪼개기 방·위반건축물 표기), 임대차계약서 특약사항의 미묘한 독소조항, 신탁원부 등 **비정형 다중 문서 간의 모순(예: 건축물대장상 호실 면적과 등기부 표제부 불일치, 신탁부동산 수탁자 동의 누락)**을 교차 추론하지 못한다. 2024~2025년 등장한 OCR-free Document VLM과 GraphRAG를 결합해야만 복잡한 표·취소선 시각 레이아웃 보존 판독과 다중 문서 엔티티(임대인-신탁사-근저당권자-선순위보증금) 관계 추론이 동시에 가능해진다.
- **AI 적용 방식**: **OCR-free Document VLM 시각 패치 임베딩 + 멀티문서 지식그래프(GraphRAG) 교차검증 + 도구호출(실거래가 API)**.
  - 파이프라인: `[등기부·건축물대장·계약서 이미지/PDF 입력] → [ColPali/Qwen2.5-VL로 취소선·표 구조 포함 시각 엔티티 추출] → [LightRAG 기반 권리관계 그래프(소유자·채권최고액·신탁여부) 구축 + 국토부 실거래가 API 도구호출] → [깡통전세 위험도 산출 및 맞춤형 특약 문구 생성]`
- **데이터/API**:
  1. 국토교통부_연립다세대 전월세 실거래가 자료 / 매매 실거래가 자료: https://www.data.go.kr (공공데이터포털 Open API, REST/XML·JSON, 회원가입 후 활용신청 즉시 발급, 이용 조건: 공공누리 제1유형 - 출처표시, 상업적·비상업적 이용 가능).
  2. 국토교통부_건축물대장정보 서비스: https://www.data.go.kr (공공데이터포털 Open API, REST, 이용 조건: 공공누리 제1유형).
  3. 서울특별시_자치구별 전세사기 발생건수 및 부동산 실거래가 정보: https://data.seoul.go.kr (서울열린데이터광장 Open API/CSV, 이용 조건: 공공누리 제1유형).
  4. 대법원 인터넷등기소 샘플 등기부등본 PDF: https://www.iros.go.kr (공식 Open API 미제공으로 접근 조건: `"unknown"` — 해커톤에서는 사용자가 직접 발급받은 PDF/촬영본 업로드 방식으로 처리).
- **핵심 기능 3개 & 이용 흐름**:
  1. **다중 공적장부 시각 교차검증**: 등기부등본·건축물대장·계약서 초안을 스마트폰으로 촬영/업로드하면 취소선(말소등기)과 현행 유효 등기를 시각적으로 구분하고 표제부·갑구·을구·위반건축물 여부를 10초 내 교차 판독.
  2. **선순위 채권·신탁사기 지식그래프 시각화**: 임대인·신탁회사·근저당권자·가압류권자 간의 권리관계를 노드-엣지 그래프로 시각화하고, 국토부 실거래가 API를 호출해 전세가율 및 경매 낙찰가율 대비 보증금 미회수 위험액을 자동 계산.
  3. **상황별 방어 특약 자동 생성 및 수정 협상 스크립트**: 발견된 리스크(예: 근저당 말소 조건부 계약, 전세보증보험 가입 불가 시 계약 무효 및 배액배상 조항 등)에 맞춰 법적 효력이 있는 맞춤형 특약 문구와 공인중개사·임대인 설득용 대화 스크립트를 생성.
  - **이용 흐름**: 계약 전 매물 주소 입력 및 등기부·계약서 초안 사진 업로드 → VLM 레이아웃 파싱 및 실거래가 API 자동 조회 → 권리관계 그래프 및 위험 신호등(안전/주의/위험) 리포트 확인 → 맞춤형 특약 복사 및 체크리스트 다운로드.
- **하루 해커톤 MVP 범위**: 관악구 실제 빌라/다가구 사례 기반 샘플 등기부등본·건축물대장·계약서 세트 5종(근저당 과다, 신탁사기, 위반건축물, 대항력 시차 악용 등)을 준비하여, Streamlit/Next.js 웹앱에서 PDF/이미지 업로드 시 `Qwen2.5-VL`(또는 GPT-4o Vision API) + `LightRAG` + 국토부 실거래가 API가 실시간 연동되어 권리관계 그래프와 특약 조항을 출력하는 전 과정 라이브 데모(추정: 9시간 내 프론트엔드 3시간, VLM·GraphRAG 파이프라인 4시간, 실거래가 API 연동 2시간).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **안심전세 App**(주택도시보증공사 HUG, https://www.khug.or.kr ), **내집스캔**(https://www.naezipscan.com ), **집품**(https://zippoom.com ).
  - 차별점: 기존 서비스는 정형 텍스트 OCR이나 단순 시세 조회에 그쳐 취소선이 뒤섞인 종이 등기부 촬영본, 신탁원부, 수기 계약서 특약 문구 간의 **문서 간 논리적 모순(Cross-Document Contradiction)**을 찾아내지 못한다. 본 서비스는 OCR-free Document VLM 패치 판독과 GraphRAG를 결합해 다중 문서 간 정합성을 직접 추론한다.
- **관련 논문/근거 1~3개**:

  3. *LightRAG: Simple and Fast Retrieval-Augmented Generation*, 2024, `arXiv:2410.05779` (https://arxiv.org/abs/2410.05779 )
- **리스크**:
  - **법적 리스크**: 변호사법 및 공인중개사법상 유권해석이나 법률 대리로 오인될 소지가 있으므로, 모든 결과 화면에 "참고용 AI 권리분석 정보이며 법적 효력을 보증하지 않음" 면책 고지(Disclaimer) 및 서울주거포털 무료 법률상담 연결 버튼 필수 배치.
  - **개인정보 리스크**: 등기부·계약서 내 주민등록번호 뒷자리 등은 클라이언트 단(브라우저 Canvas)에서 정규식·영역 마스킹 후 API로 전송.

### 2. 듀플렉스쉴드 (DuplexShield) — 통화 중 딥페이크 음성 탐지 및 실시간 끼어들기(Full-Duplex) 보이스피싱 방어 에이전트
- **주요 사용자**: 기관사칭형(검찰·금감원 사칭) 보이스피싱에 취약한 2030 사회초년생 및 지인사칭·대출사기에 취약한 60대 이상 고령층.
- **문제**: 경찰청 및 금융감독원 통계에 따르면 보이스피싱 피해액은 2024년 약 8,545억 원(23,112건)에서 **2025년 약 1조 2,578억 원(1인당 평균 피해액 약 5,384만 원)으로 사상 최초 1조 원을 돌파**했으며, 특히 검찰·금감원 등을 사칭하는 '기관사칭형' 피해액이 9,884억 원으로 전체의 **78.6%**를 차지한다 (출처: 금융위원회·금융감독원·경찰청 관련 보도 및 통계 https://www.fsc.go.kr , https://www.fss.or.kr ).
- **왜 AI여야 하나**: 기존의 키워드 필터링이나 통화 종료 후 사후 분석 앱은 피해자가 심리적 지배(가스라이팅)를 당해 원격제어 앱을 설치하거나 송금하는 골든타임을 막지 못한다. 2024~2025년 최초로 등장한 **Full-Duplex Speech-to-Speech 모델(통화 오디오 스트림을 동시에 듣고 실시간 개입하는 양방향 음성 기술)**과 **국소 오디오 딥페이크 워터마크/스푸핑 탐지 기술**이 결합되어야만, 약 200ms 이내 지연시간으로 통화 맥락과 음성 합성을 실시간 감지하고 피해자 귀에만 즉시 경고음·음성 코칭("지금 검찰 사칭 수법입니다, 사건번호를 물어보세요")을 속삭여줄 수 있다.
- **AI 적용 방식**: **실시간 오디오 딥페이크/합성음 탐지 + Full-Duplex Speech-to-Speech 스트리밍 에이전트 + 금감원 사기수법 RAG**.
  - 파이프라인: `[실시간 양방향 통화 오디오 스트림 입력] → [16kHz 프레임 단위 합성음 탐지(AudioSeal/SSL) + Full-Duplex 음성 모델(Moshi/Freeze-Omni/Realtime API)의 대화 맥락 분석] → [위험 임계치 도달 시 피해자 채널로 실시간 음성 개입(Whispering Coaching) 및 보호자 알림 도구호출]`
- **데이터/API**:
  1. 금융감독원_보이스피싱 지킴이 (그놈 목소리 실제 사기범 음성 및 피해사례 데이터): https://www.fss.or.kr/fss/main/sub1voice.do?menuNo=200012 (금융감독원 공개 자료, 접근 방법: 웹 공개 오디오/스크립트 열람, 이용 조건: 공공누리 기준에 따르나 세부 API 라이선스는 `"unknown"`이므로 공개 텍스트 수법 요약본을 RAG 지식베이스로 구축).
  2. AI-Hub 한국어 음성 데이터셋 및 스푸핑 검증용 오픈 데이터셋 (ASVspoof 2021/2024): https://www.aihub.or.kr / https://www.asvspoof.org (연구·비상업적/경진대회 활용 가능, CC BY 4.0 또는 오픈 라이선스).
  3. 경찰청_사이버범죄/전화금융사기 예방 공공데이터: https://www.data.go.kr (공공데이터포털, 공공누리 제1유형).
- **핵심 기능 3개 & 이용 흐름**:
  1. **초저지연(Sub-second) 가스라이팅 화법 및 딥페이크 음성 동시 탐지**: 통화 상대방의 음성이 AI 보이스클로닝 합성음인지 파형 단위로 검사함과 동시에, "구속영장", "보안계좌", "원격지원 앱" 등 강압적 심리 지배 흐름을 실시간 점수화.
  2. **Full-Duplex 귓속말 개입(Whispering Interjection)**: 피해자가 당황해 대답하려 할 때 통화를 끊지 않고도 피해자에게만 들리는 인이어(In-ear) 음성으로 "실제 검사는 전화로 자금 이체를 요구하지 않습니다. 지금 제가 대신 확인 질문을 던질까요?"라고 즉시 개입.
  3. **대리 방어 응답(AI Call Screening) 및 원클릭 금융 차단 안내**: 사용자가 'AI 방어 전환' 버튼을 누르면 AI 에이전트가 통화 주도권을 넘겨받아 사기범에게 법적 절차 검증 질문을 던져 사기범의 통화 포기를 유도하고, 여신거래 안심차단 서비스 신청 화면을 즉시 띄움.
  - **이용 흐름**: 의심 전화 수신 시 스피커폰/앱 브릿지 활성화 → 실시간 딥페이크 확률 게이지 및 가스라이팅 위험도 시각화 → 위험 감지 시 AI의 실시간 귓속말 코칭 수신 → 'AI 대리 응대' 클릭으로 사기범 격퇴 및 가족/112 요약 리포트 전송.
- **하루 해커톤 MVP 범위**: 웹 브라우저에서 두 명의 발표자(사기범 역할 vs 피해자 역할) 또는 녹음된 '그놈 목소리' 오디오와 AI 보이스클로닝 샘플을 재생할 때, WebRTC 오디오 스트림을 통해 실시간으로 딥페이크 판별 스코어가 올라가고 Full-Duplex 음성 에이전트(OpenAI Realtime API 또는 로컬 `Freeze-Omni`/`Moshi` 경량 파이프라인)가 즉석에서 끼어들어 방어 코칭을 수행하는 듀얼 화면 라이브 시연(추정: 개발 소요시간 8시간).

### 3. 마우스벗 GUI (MouseBud GUI) — 고령층·디지털 취약계층을 위한 순수 비전 기반 공공웹·민원 화면 시각 코칭 및 대리 조작 에이전트
- **주요 사용자**: 정부24, 국민건강보험, 코레일 예매, 복지포털 등 복잡한 웹·앱 인터페이스를 스스로 다루기 어려운 60대 이상 고령층 및 디지털 취약계층(관악·금천 노인복지관 및 주민센터 방문자).
- **문제**: 과학기술정보통신부와 한국지능정보사회진흥원(NIA)의 《디지털정보격차 실태조사》에 따르면, 고령층의 디지털 정보화 종합 수준은 일반 국민(100 기준) 대비 **약 71%대(4대 취약계층 중 최하위)**이며, 특히 기기 보유를 뜻하는 '접근 수준'(약 95%)은 높으나 실제 소프트웨어를 조작하는 **'역량 수준'은 50%대(70대 이상은 더욱 급감)**에 머무는 **'접속된 배제(Connected Exclusion)'** 현상이 심각하다 (출처: 국가통계포털 KOSIS https://kosis.kr , 지표누리 e-나라지표 https://www.index.go.kr ).
- **왜 AI여야 하나**: 기존 웹 접근성 도구(스크린리더, 단순 돋보기)나 정해진 HTML DOM 셀렉터 기반 매크로(RPA)는 사이트 개편, 팝업창 등장, Canvas 기반 키오스크/복잡한 공공웹 화면에서 즉시 작동 불능에 빠진다. 2024~2025년 급부상한 **순수 비전 기반 GUI 그라운딩 에이전트(Pure-Vision GUI Agent, 예: Microsoft OmniParser V2)** 기술을 적용해야만 화면 픽셀만 보고도 작은 아이콘·버튼의 바운딩 박스와 기능을 실시간 파싱하여 사용자의 음성 명령을 마우스 좌표 안내로 변환할 수 있다.
- **AI 적용 방식**: **Pure-Vision 화면 요소 파싱(OmniParser V2) + 멀티모달 행동 계획 에이전트(Computer-Use Agent) + 음성 대화(STT/TTS)**.
  - 파이프라인: `[사용자 화면 캡처 스트림 + 음성 요청("건강보험 자격득실확인서 뽑아줘")] → [OmniParser V2가 화면 내 모든 클릭 가능 UI 요소에 번호·바운딩박스 부여(Set-of-Mark)] → [VLM이 현재 화면 상태에서 누를 버튼 ID 결정] → [화면 위 거대 형광 화살표 오버레이 표시 + 음성 안내(또는 사용자 승인 시 Playwright 자동 클릭)]`

  1. Microsoft OmniParser V2 오픈소스 모델 가중치 및 코드: https://github.com/microsoft/OmniParser (접근 방법: GitHub 및 Hugging Face 공개 다운로드, 이용 조건: MIT License 코드 / 모델별 오픈 라이선스).

### 4. 폴리시메이트 Graph (PolicyMate Graph) — 중앙부처·서울시·관악·금천 청년정책 지식그래프(GraphRAG) 자격추론 및 사업계획서 코파일럿
- **주요 사용자**: 관악구·금천구 거주 청년(대학생, 취준생, 초기 창업가, 프리랜서) 및 금천청년꿈터·관악청년청 이용자.
- **문제**: 국무조정실·보건복지부 등에 따르면 청년층 대상 주거·금융·취업·창업 지원 정책은 중앙부처와 지자체를 합쳐 수천 개에 달하지만, 정책마다 소득 기준(중위소득 vs 도시근로자 월평균소득), 거주 기간, 중복 수혜 금지 조항이 파편화되어 있어 수혜 자격 오판 및 탈락이 빈번하다. 특히 관악구는 전체 가구의 약 63% 이상이 1인가구이며 그중 2030 청년 비중이 60% 이상을 차지해 맞춤형 정책 탐색 수요가 폭발적이다 (출처: 관악구청 https://www.gwanak.go.kr , 서울열린데이터광장 https://data.seoul.go.kr ).
- **왜 AI여야 하나**: 기존 키워드 검색 포털(온통청년, 보조금24)은 단일 정책 공고문만 보여줄 뿐, **"A 정책(서울시 청년월세)을 받으면 B 정책(국토부 청년월세 한시특별지원)이나 C 정책(관악구 이사비 지원)과 중복 수혜가 가능한지, 어떤 순서로 신청해야 총 수혜액이 극대화되는지"**와 같은 다중 문서 간 전역적·복합적 추론(Multi-hop & Global Reasoning)을 수행하지 못한다. 2024년 발표된 Microsoft `GraphRAG`와 `HippoRAG` 기술을 적용해 정책 간 배타성·선후관계·자격요건을 지식그래프로 색인해야만 정확한 조합 최적화가 가능하다.
- **AI 적용 방식**: **정책 공고문 엔티티-관계 지식그래프(GraphRAG / HippoRAG) + 자격요건 검증 도구호출(계산기 API) + 신청서 초안 생성**.
  - 파이프라인: `[중앙·서울시·관악·금천 공고문 수집] → [정책명·연령·소득기준·중복불가조항을 GraphRAG 지식그래프로 구조화] → [사용자 프로필 대화 입력 시 Personalized PageRank(HippoRAG) 다중 홉 탐색 + 중위소득 계산 도구호출] → [최적 신청 로드맵(연간 타임라인) 및 자기소개서/활용계획서 초안 생성]`
- **데이터/API**:
  1. 한국고용정보원_온통청년(청년정책) Open API: https://www.youthcenter.go.kr (접근 방법: 온통청년 오픈API 신청 후 인증키 발급, XML/JSON, 이용 조건: 출처 표시 조건부 무료 개방, 세부 상업적 제한 여부는 `"unknown"`).
  2. 행정안전부_대한민국 공공서비스 정보(보조금24) Open API: https://www.data.go.kr (공공데이터포털, REST/JSON, 이용 조건: 공공누리 제1유형).
  3. 서울특별시_몽땅정보만능키(서울청년포털) 정책 정보: https://youth.seoul.go.kr 및 https://data.seoul.go.kr (서울열린데이터광장 Open API, 이용 조건: 공공누리 제1유형).
- **핵심 기능 3개 & 이용 흐름**:
  1. **중복 수혜·배타 조건 다중 홉 그래프 추론**: 사용자의 나이, 거주지(예: 관악구 대학동), 가구 건강보험료, 재학/취업 상태를 입력하면 상호 배타적인 정책을 걸러내고 연간 총 수혜 금액을 극대화하는 '정책 조합 포트폴리오'를 그래프 형태로 제시.
  2. **근거 조항 하이라이팅 인용(Zero-Hallucination Citation)**: 왜 특정 정책이 가능하거나 불가능한지 원본 공고문 PDF의 정확한 문단과 페이지(예: "2026년 관악구 청년 공고문 4p 제외대상 2호")를 인용 표시.
  3. **금천청년꿈터·창업지원금 맞춤형 신청서·사업계획서 초안 작성**: 청년 공간 입주 신청이나 초기 창업 지원사업 지원 시, 해당 공고의 평가항목(배점표)을 자동 분석해 사용자 이력 기반 문항별 초안을 생성.
  - **이용 흐름**: 1분 대화형 프로필 입력 → 내 조건에 맞는 중앙+서울시+자치구 정책 지식그래프 탐색 → 중복 불가 충돌 제거된 '연간 최대 수혜 캘린더' 확인 → 원클릭으로 신청 사유서/계획서 초안 생성.
- **하루 해커톤 MVP 범위**: 서울시·관악구·금천구 주요 청년 정책 50여 개의 실제 공고문과 온통청년 API를 연동하여 구축한 지식그래프 위에서, 사용자 페르소나 입력 시 (1) 일반 벡터 RAG가 놓치는 중복 수혜 금지 조항을 GraphRAG가 정확히 잡아내는 비교 시연, (2) 연간 최적 신청 로드맵 및 신청서 자동 생성 시연(추정: 9시간 내 구현 가능).

  - 경쟁 서비스: **온통청년**(https://www.youthcenter.go.kr ), **보조금24**(정부24, https://www.gov.kr ), **열고닫기**(https://www.opcl.kr ).
  - 차별점: 기존 플랫폼은 단순 필터 검색에 그쳐 여러 정책 간의 상호 충돌(중복 수혜 불가)과 시간적 신청 순서를 조합해주지 못한다. 본 서비스는 GraphRAG/HippoRAG 기반 다중 홉 추론으로 **'정책 간 조합 최적화'**와 **'배점표 기반 신청서 작성'**을 한 번에 해결한다.

### 5. 세이프캠 VLM (SafeCam VLM) — 소규모 제조·물류 사업장(G밸리 등) 작업 영상을 통한 산업재해·근골격계 위험 실시간 시공간의미 진단 플랫폼
- **주요 사용자**: 금천구·구로구(G밸리) 및 서울 시내 50인 미만 소규모 제조·인쇄·의류봉제·물류 작업장 사업주 및 안전보건담당자.
- **문제**: 고용노동부 산업재해 현황 통계에 따르면, 전체 재해조사 대상 사고사망자 중 **50인 미만(건설업 50억 미만) 소규모 사업장 사망자 비중은 약 60.9%(2026년 3분기 누적 366명 중 223명, 과거 유족급여 승인 기준 70~80%대)**에 달하며, 중대재해처벌법이 50인 미만 사업장까지 전면 확대 적용되었음에도 전문 안전관리자를 채용할 여력이 없는 영세 사업장이 대부분이다 (출처: 고용노동부 산업재해 현황 통계 https://www.moel.go.kr , e-나라지표 https://www.index.go.kr ).
- **왜 AI여야 하나**: 기존 컴퓨터 비전(단순 YOLO 객체 탐지)은 안전모 착용 여부 같은 정적 객체만 판별할 뿐, **"작업자가 지게차 사각지대에서 불안정한 자세로 무거운 박스를 비틀어 들어 올리는 연속 동작"**이나 **"프레스 기계 방호장치를 임의로 해제하고 손을 넣는 시공간적 작업 맥락(Spatiotemporal Context)"**은 사전 학습된 클래스가 없으면 전혀 인식하지 못한다. 2024~2025년 발전한 **장기 비디오 시공간 압축 VLM(LongVU, Qwen2-VL)**과 3D 포즈 추정을 결합해야만 별도 고가 센서 없이 스마트폰 15초 작업 영상만으로 복합 위험 행동과 법정 위험성평가서를 자동 생성할 수 있다.
- **AI 적용 방식**: **시공간 비디오 VLM(LongVU / Qwen2-VL) + 3D 인체 포즈 추출(MediaPipe) 기반 인간공학 지표(REBA/RULA) 계산 + 산안법 규칙 RAG**.
  - 파이프라인: `[스마트폰 15초 작업 영상 입력] → [MediaPipe 3D 관절 각도 추출로 REBA/RULA 근골격계 부하 점수 산출 + Qwen2-VL 비디오 토큰 분석으로 주변 설비·협착·추락 위험 맥락 판독] → [안전보건공단 업종별 유해위험요인 RAG 매칭] → [법정 양식 위험성평가표 및 개선대책 자동 생성]`
- **데이터/API**:
  1. 한국산업안전보건공단_업종별 유해위험요인 및 안전보건자료 API/데이터: https://www.data.go.kr (공공데이터포털 Open API, REST/JSON, 이용 조건: 공공누리 제1유형).
  2. 국가법령정보센터_산업안전보건기준에 관한 규칙 Open API: https://open.law.go.kr (접근 방법: 무료 계정 신청 후 Open API 활용, XML/JSON, 이용 조건: 공공누리 제1유형).
  3. AI-Hub 산업안전 및 작업자 행동 영상 데이터셋(참조용): https://www.aihub.or.kr (이용 조건: AI-Hub 데이터 사용 허가 규정 준수).
- **핵심 기능 3개 & 이용 흐름**:
  1. **15초 작업 영상 시공간 위험요인 자동 타임스탬프 태깅**: 스마트폰으로 작업 현장을 촬영해 올리면 비디오 VLM이 영상 내 시간 구간별로 '끼임 위험(00:04~00:08)', '부적절한 중량물 들기(00:09~00:13)' 등 복합 위험 맥락을 자연어와 바운딩박스로 적출.
  2. **관절 각도 기반 근골격계 부담작업(REBA/RULA) 자동 채점**: 영상 속 작업자의 척추·어깨·무릎 3차원 굴곡 각도를 추출해 결정론적 수식으로 인간공학적 위험 등급(1~4등급)을 자동 산출.
  3. **중대재해처벌법 대비 원클릭 '위험성평가서' PDF 자동 발행**: 영세 사업주가 가장 어려워하는 행정 서류인 '상시 위험성평가 결과표(유해위험요인 파악 → 위험성 추정 → 감소대책 수립 → 관련 법령 조항)'를 촬영 사진과 함께 법정 양식 PDF로 즉시 출력.
  - **이용 흐름**: 현장 작업 15초 촬영 업로드 → AI 시공간 위험 구간 분석 및 관절 각도 시각화 확인 → 안전보건공단 표준 개선대책 선택 → 법정 위험성평가서 PDF 원클릭 다운로드 및 근로자 다국어 안전수칙 공유.
- **하루 해커톤 MVP 범위**: 물류 상하차/작업 시연 영상(또는 현장에서 팀원이 직접 박스를 들고 작업하는 웹캠 실시간 영상)을 입력받아, (1) MediaPipe 관절 각도 오버레이 및 REBA 점수 산출, (2) `Qwen2-VL`/`Qwen2.5-VL`이 시공간 작업 위험요인을 진단하고, (3) 산업안전보건기준 규칙 조항이 인용된 위험성평가표 PDF를 즉석 생성하는 시연(추정: 9시간 내 구현 가능).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **안전보건공단 위험성평가 지원시스템(KRAS)**(https://kras.kosha.or.kr ), **세이프티스냅(SafetySnap)** 등 CCTV 관제 솔루션.
  - 차별점: KRAS는 사업주가 직접 텍스트를 검색·입력해야 해 고령 영세 사업주가 쓰기 어렵고, 기업용 CCTV 관제 솔루션은 수천만 원의 구축비가 든다. 본 서비스는 **설치비 0원 스마트폰 짧은 영상**만으로 시공간 맥락 진단부터 법정 서류 생성까지 끝낸다.
- **관련 논문/근거 1~3개**:
  1. *LongVU: Spatiotemporal Adaptive Compression for Long Video-Language Understanding*, 2024, `arXiv:2410.17434` (https://arxiv.org/abs/2410.17434 )
  2. *Qwen2-VL: Enhancing Vision-Language Model's Perception of the World at Any Resolution*, 2024, `arXiv:2409.12191` (https://arxiv.org/abs/2409.12191 )
- **리스크**:
  - **개인정보·노동감시 리스크**: 근로자 얼굴 노출 및 작업 감시 도구 악용 우려 → 영상 업로드 즉시 클라이언트/전처리 단계에서 얼굴 자동 블러(Gaussian Blur) 처리 후 분석 및 원본 영상 즉시 파기.
  - **법적 리스크**: AI 평가서만 믿고 현장 점검을 소홀히 할 위험 → 사업주 최종 서명 확인 절차 및 "안전보건공단 컨설팅 연계" 안내 포함.

### 6. 온마음 SLM (On-Maum SLM) — 고립·은둔 위기 청년을 위한 100% 온디바이스(Zero-Server) 초경량 에이전트 및 소셜 브릿지
- **주요 사용자**: 대인기피, 취업 실패, 우울감 등으로 외부 소통을 단절하거나 은둔 초기 징후를 보이는 2030 청년(관악·금천 1인가구 청년 및 대학생) 중 클라우드 서버에 자신의 민감한 심리·일상이 기록되는 것을 극도로 꺼리는 사용자.
- **문제**: 보건복지부와 국무조정실(한국보건사회연구원)의 실태조사에 따르면, 전체 청년 인구의 약 **5%(약 5%~5.2%)에 해당하는 최대 약 54만 명**이 고립·은둔 위기 상태에 놓여 있으며, 은둔 기간이 길어질수록 사회 복귀 비용이 기하급수적으로 증가한다 (출처: 보건복지부 https://www.mohw.go.kr , 한국개발연구원 KDI/국회예산정책처 https://www.nabo.go.kr ).
- **왜 AI여야 하나**: 고립·은둔 청년들은 타인의 시선과 개인정보 유출에 극도로 민감하여 대면 상담은 물론, 대화 내용이 외부 기업 서버(OpenAI 등)로 전송되는 클라우드 AI 챗봇조차 기피하는 경향이 있다. 2024~2025년 비약적으로 발전한 **Sub-billion~2B급 온디바이스 소형 언어모델(On-Device SLM: MobileLLM, Octopus v2)**과 브라우저 내 WebGPU 추론 기술을 활용해야만 **네트워크를 완전히 끊은 상태(비행기 모드)에서도 스마트폰/노트북 로컬 자원만으로 공감 대화와 로컬 함수 호출(일정 알림, 단계별 외출 미션 생성)**을 수행할 수 있다.
- **AI 적용 방식**: **WebGPU/로컬 기반 On-Device SLM 추론 + 온디바이스 Function Calling(Octopus v2 아키텍처 응용) + 행동활성화치료(BA) 마이크로 미션 추천**.
  - 파이프라인: `[사용자 음성/텍스트 일기 입력(외부 서버 전송 0바이트)] → [브라우저 내 WebLLM/Ollama 기반 로컬 SLM이 감정 상태 및 활동성 수준 분석] → [온디바이스 Function Calling으로 로컬 캘린더에 초소형 일일 회복 미션("창문 열고 햇빛 사진 찍기", "금천청년꿈터 무인 프로그램 방문") 등록]`
- **데이터/API**:
  1. 서울특별시_고립·은둔 청년 지원사업 및 청년마음건강 지원 정보: https://youth.seoul.go.kr / https://data.seoul.go.kr (서울열린데이터광장 공공데이터, 로컬 JSON DB로 앱 내 사전 번들링하여 오프라인 상태에서도 참조, 이용 조건: 공공누리 제1유형).
  2. 국립정신건강센터_정신건강 자가검진 도구(PHQ-9, GAD-7 표준 문항) 및 복지서비스 정보: https://www.ncmh.go.kr / https://www.data.go.kr (공공데이터포털, 이용 조건: 공공누리 제1유형).
  3. 오픈소스 소형 언어모델 가중치 (Qwen2.5-1.5B-Instruct / Llama-3.2-1B-Instruct 등 WebLLM 호환 모델): https://huggingface.co (이용 조건: Apache 2.0 / Llama 3.2 Community License).
- **핵심 기능 3개 & 이용 흐름**:
  1. **Zero-Server 에어갭(Air-Gapped) 마음일기 및 인지왜곡 교정**: 와이파이를 끈 상태에서도 100% 기기 내부(WebGPU)에서 동작하는 AI 에이전트와 대화하며, 흑백논리·과잉일반화 등 부정적 자동사고를 부담 없이 털어놓고 재구조화.
  2. **온디바이스 기능 호출(Function Calling) 기반 '마이크로 루틴' 자동 처방**: 대화 맥락에서 수면 역전이나 무기력 징후가 포착되면 로컬 함수 호출을 통해 난이도 1단계("물 한 컵 마시기")부터 5단계("관악구 청년공간 조용한 독서모임 가기")까지 행동활성화 미션을 로컬 알람으로 자동 설정.
  3. **프라이버시 보존형 익명 지원사업 브릿지**: 사용자가 사회적 연결 준비가 되었을 때만, 원본 대화록은 절대 내보내지 않고 로컬에서 요약된 '관심 키워드'만으로 서울시 고립은둔청년 지원사업 및 금천청년꿈터 프로그램을 매칭.
  - **이용 흐름**: 웹앱 접속(초기 모델 캐싱 후 네트워크 차단 가능) → 오늘 기분 및 일상 대화 → 온디바이스 SLM의 공감 피드백 및 오늘의 5분 행동 미션 카드 발급 → 미션 달성 스탬프 누적 시 지역 청년센터 비대면/소규모 프로그램 추천 확인.
- **하루 해커톤 MVP 범위**: 심사위원 앞에서 **실제로 노트북 와이파이를 끄고(오프라인 증명)** 브라우저 WebGPU(WebLLM) 또는 로컬 런타임에서 1B~2B 소형 모델이 즉각 응답하며, 사용자의 무기력 대화로부터 로컬 JSON 캘린더/미션 함수를 정확히 호출(Function Calling)하고 관악·금천 청년 프로그램을 추천하는 시연(추정: 9시간 내 구현 가능).

  - 차별점: 기존 서비스는 모든 심리 상담 로그가 기업 클라우드 DB에 저장되어 고립·은둔 청년의 불안을 유발한다. 본 서비스는 **100% 온디바이스 SLM과 로컬 함수 호출**로 동작하여 데이터 유출 가능성을 원천 제거(Zero-Trust Privacy)한다.

### 7. 스페이셜아이 3D (SpatialEye 3D) — 단안 카메라 실시간 깊이 추정(Depth Estimation)과 3D 공간 VLM을 결합한 보행약자·시각장애인 골목길 내비게이터
- **주요 사용자**: 가파른 경사로와 좁은 골목길, 불법 적치물이 많은 관악구·금천구 일대를 이동하는 시각장애인, 휠체어 이용자, 유모차 동반자 및 고령 보행약자.
- **문제**: 국토교통부 《교통약자 이동편의 실태조사》(2024년 말 기준)에 따르면, 국내 전체 교통약자 수는 약 **1,613만 명으로 전체 인구의 31.5%(국민 약 3명 중 1명)**에 달하며, 보건복지부 등록장애인(약 262.7만 명) 중 시각장애인은 9.3%, 지체장애인은 42.4%를 차지한다 (출처: 국토교통부 https://www.molit.go.kr , 보건복지부 https://www.mohw.go.kr ). 그러나 기존 보행 내비게이션은 인도 위 돌출 볼라드, 파손된 점자블록, 급경사 턱, 전동킥보드 방치물 등 실시간 3차원 보행 장애물을 안내하지 못한다.
- **왜 AI여야 하나**: 기존 GPS 내비게이션은 2D 도로망만 알 뿐 눈앞 2m 거리의 턱 높이나 전동킥보드 방치 여부를 모른다. 또한 고가의 LiDAR 장비(아이폰 Pro 기종 전용 등)가 없는 일반 보급형 스마트폰에서는 거리 측정이 불가능했다. 2024년 발표된 **단안 카메라 초정밀 깊이 추정 모델(Depth Anything V2)**과 **3차원 공간 추론 VLM(SpatialVLM)**을 결합하면, 일반 스마트폰 카메라 영상 1장만으로도 장애물까지의 미터(m) 단위 거리·방향·통과 가능 폭을 실시간 3D 공간 언어로 추론할 수 있다.
- **AI 적용 방식**: **단안 깊이 추정(Depth Anything V2) + 3D 공간 추론 VLM(SpatialVLM 아키텍처 응용) + 서울시 보행약자 GIS 데이터 결합**.
  - 파이프라인: `[스마트폰 전방 카메라 프레임 입력] → [Depth Anything V2로 픽셀별 상대/절대 깊이 맵(Depth Map) 생성] → [RGB 이미지 + 깊이 맵을 VLM에 주입하여 "전방 2.5m 우측에 전동킥보드가 점자블록을 막고 있음, 좌측 1.2m 여유 공간으로 우회" 추론] → [공간 음향(Spatial Audio) TTS 안내 + 지자체 불편신고 자동 생성]`
- **데이터/API**:
  1. Depth Anything V2 오픈소스 모델 가중치: https://github.com/DepthAnything/Depth-Anything-V2 (접근 방법: Hugging Face / GitHub 다운로드, 이용 조건: Depth-Anything-V2-Small은 Apache-2.0 License).
  2. 서울특별시_교통약자 이동편의시설 및 보행네트워크 공간정보: https://data.seoul.go.kr (서울열린데이터광장 Open API / SHP·CSV, 이용 조건: 공공누리 제1유형).
  3. 국토교통부_전국 보행자전용도로 및 육교/지하보도 표준데이터: https://www.data.go.kr (공공데이터포털, 이용 조건: 공공누리 제1유형).
- **핵심 기능 3개 & 이용 흐름**:
  1. **LiDAR 없는 단안 카메라 실시간 3D 거리·폭 음성 코칭**: 일반 웹캠/스마트폰 카메라 영상에서 깊이 맵을 실시간 생성하여, 전방 단차(계단/경사로), 방치된 킥보드, 볼라드까지의 거리(m)와 휠체어 통과 가능 폭을 스테레오 방향음과 음성으로 안내.
  2. **점자블록 파손·불법 적치물 공간 인지 및 회피 경로 제시**: 단순 사물 이름 나열("자전거 있음")이 아니라 공간적 관계("점자블록 위에 자전거가 쓰러져 있으니 왼쪽으로 두 걸음 이동하세요")를 추론해 행동 지침 제공.
  3. **서울시 보행 불편 지점 자동 크라우드소싱 맵핑**: 주행 중 반복 감지된 파손 점자블록·급경사·상습 적치물 위치(GPS 좌표 + Depth 시각화 이미지)를 서울시 보행안전 지도에 자동 핀 등록 및 다산콜센터(120) 민원 포맷으로 변환.
  - **이용 흐름**: 앱 실행 후 목적지 음성 입력 → 서울시 보행약자 무장애 경로 매칭 → 이동 중 카메라가 실시간 Depth Map + VLM 공간 분석 수행 → 이어폰을 통해 3D 거리·회피 방향 음성 수신.
- **하루 해커톤 MVP 범위**: 해커톤 현장에서 웹캠/스마트폰 카메라로 복도 장애물(의자, 가방, 바닥 테이프 유도선)을 비추면 화면 좌측에 실시간 컬러 Depth Map(`Depth Anything V2-Small`)이 렌더링되고, 우측에서 VLM이 장애물까지의 거리(m)와 회피 방향("전방 1.8m 의자, 우측 90cm 공간 통과 가능")을 실시간 음성으로 안내하는 고임팩트 비전 데모(추정: 9시간 내 구현 가능).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **Be My Eyes (Be My AI)**(https://www.bemyeyes.com ), **설리번 플러스**(투아트, https://www.tuat.kr ).
  - 차별점: 기존 앱들은 정지 사진 1장을 찍어 VLM으로 장면 묘사만 해줄 뿐, **단안 깊이 추정(Metric/Relative Depth Map)을 결합한 정량적 거리(m)·통과 폭 계산**과 서울시 보행 GIS 결합을 제공하지 못한다.
- **관련 논문/근거 1~3개**:
  1. *Depth Anything V2*, 2024 (NeurIPS 2024), `arXiv:2406.09414` (https://arxiv.org/abs/2406.09414 )
  2. *SpatialVLM: Endowing Vision-Language Models with Spatial Reasoning Capabilities*, 2024 (CVPR 2024), `arXiv:2401.12168` (https://arxiv.org/abs/2401.12168 )
- **리스크**:
  - **안전 리스크**: 카메라 사각지대(발밑 구멍 등)나 야간 역광 시 깊이 추정 오차로 인한 보행 사고 위험 → 반드시 흰지팡이 등 기존 보조기구와 병행 사용하도록 강제 안내하며, 프레임 신뢰도 저하 시 즉시 진동 경고 발생.
  - **개인정보 리스크**: 거리 행인 얼굴 촬영 → 실시간 Depth 추출 후 배경 인물 얼굴 마스킹.

### 8. 메디렌즈 KG (MediLens KG) — 다제약물 복용 어르신·만성질환자를 위한 약봉투·낱알 VLM 판독 및 식약처 DUR 상호작용 검증 에이전트
- **주요 사용자**: 여러 진료과(내과·정형외과·안과 등)에서 처방받은 약과 건강기능식품을 동시에 복용하는 65세 이상 어르신 및 그들을 돌보는 자녀·요양보호사.
- **문제**: 국민건강보험공단 통계에 따르면 고혈압·당뇨 등 만성질환을 진단받고 **서로 다른 성분의 약을 10종류 이상(60일 이상) 상시 복용하는 '다제약물' 복용자가 170만 명을 돌파**했으며, 이 중 **65세 이상 노인이 약 80~82%**를 차지한다. 그러나 건보공단 다제약물 관리 시범사업 참여율은 전체 대상의 1% 미만에 불과하여 약물 상호작용으로 인한 어지러움, 낙상, 응급실 입원 위험이 방치되고 있다 (출처: 국민건강보험공단 https://www.nhis.or.kr , 일산병원 연구소 https://www.nhimc.or.kr ).
- **왜 AI여야 하나**: 어르신들이 보유한 구겨진 약봉투, 조제약국마다 다른 표기 양식, 봉투에서 꺼내놓은 알약(낱알), 그리고 해외 직구 영양제 라벨을 한꺼번에 찍었을 때 기존 바코드/단순 OCR은 약품명을 정확히 매핑하지 못한다. **고해상도 멀티모달 VLM(InternVL 2.5 / Qwen2.5-VL)**의 시각 인식과 **식약처 의약품안전사용(DUR) Open API 도구호출 에이전트**를 결합해야만 사진 한 장에서 여러 처방전·약봉투·영양제 성분을 추출하고 병용금기·노인주의·효능군 중복 여부를 결정론적으로 교차 검증할 수 있다.
- **AI 적용 방식**: **고해상도 약봉투·라벨 VLM 파싱 + 식약처 DUR/e약은요 Open API 도구호출(Tool-Calling Agent) + 어르신 맞춤형 큰글씨·음성 복약 스케줄러**.
  - 파이프라인: `[여러 병원 약봉투·영양제 라벨 다중 이미지 입력] → [VLM이 약품명·성분명·1일 복용횟수 추출] → [식약처 DUR 품목정보 API 및 e약은요 API 자동 도구호출로 병용금기·연령주의·성분중복 검증] → [충돌 경고 리포트 + 시간대별(아침/점심/저녁) 음성·색상 복약 시간표 생성]`
- **데이터/API**:
  1. 식품의약품안전처_의약품안전사용서비스(DUR) 품목정보 Open API: https://www.data.go.kr (공공데이터포털, REST/XML·JSON, 병용금기·노인주의·효능군중복 정보 제공, 이용 조건: 공공누리 제1유형).
  2. 식품의약품안전처_의약품개요정보(e약은요) Open API: https://www.data.go.kr (공공데이터포털, REST/XML·JSON, 효능·사용법·상호작용·부작용 제공, 이용 조건: 공공누리 제1유형).

### 9. 로컬비즈 데이터인터프리터 (LocalBiz Interpreter) — 관악·금천 골목상권 소상공인을 위한 자율 코드실행 상권분석 및 멀티모달 마케팅 생성 에이전트
- **주요 사용자**: 관악구(샤로수길·신림역 일대)·금천구(가산·독산 맛나는거리 등)의 음식점·소매업 등 1인 자영업자 및 예비 소상공인.
- **문제**: 국세청 국세통계에 따르면 개인·법인 사업자를 포함한 **연간 폐업 신고자 수가 사상 최초로 100만 명(약 100만 8,000여 명, 폐업률 약 9%대)을 돌파**했으며, 그중 소매업과 음식점업 등 영세 골목상권 자영업자에 폐업이 집중되고 있다 (출처: 국세청 국세통계포털 TASIS https://tasis.nts.go.kr ). 서울시 등 지자체가 방대한 상권 빅데이터를 개방하고 있으나, 1인 소상공인은 통계표를 해석하거나 데이터 기반 마케팅을 실행할 시간이 없다.
- **왜 AI여야 하나**: 기존 상권분석 포털은 복잡한 지도와 수십 개의 표만 나열할 뿐, 사장님이 "비 오는 평일 저녁 우리 동네 20대 여성 유동인구가 줄어들 때 어떤 메뉴 세트를 당근마켓/인스타그램에 올려야 할까?"라고 물었을 때 데이터를 스스로 교차 분석해 실행물까지 만들어주지 못한다. 2024년 등장한 **자율 코드 실행 데이터 분석 에이전트(Data Interpreter)**와 **멀티모달 이미지·카피 생성 파이프라인**을 결합해야만 공공 상권 API 수집 → Python 통계 검정/시각화 → 타겟 맞춤형 홍보물 제작을 원스톱으로 자동화할 수 있다.
- **AI 적용 방식**: **자율 코드 작성·실행 에이전트(Data Interpreter 아키텍처) + 서울시 상권분석 Open API 도구호출 + VLM/Diffusion 메뉴 판촉물 생성**.
  - 파이프라인: `[점포 위치·업종·고민 입력] → [에이전트가 서울시 우리마을가게 상권분석 API 호출 + Python 샌드박스에서 시간대·연령대별 매출/유동인구 상관분석 코드 자율 실행] → [핵심 타겟 인사이트 도출] → [매장 음식 사진 기반 맞춤형 프로모션 배너 및 SNS 카피 자동 생성]`
- **데이터/API**:
  1. 서울특별시_우리마을가게 상권분석서비스(구/신 상권 추정매출, 추정유동인구, 점포수, 상주인구): https://data.seoul.go.kr (서울열린데이터광장 Open API, REST/JSON·XML, 인증키 즉시 발급, 이용 조건: 공공누리 제1유형).
  2. 기상청_단기예보 및 지상관측 데이터 Open API: https://www.data.go.kr (공공데이터포털, 날씨별 매출 변화 분석용, 이용 조건: 공공누리 제1유형).
  3. 소상공인시장진흥공단_상가(상권)정보 Open API: https://www.data.go.kr (공공데이터포털, 이용 조건: 공공누리 제1유형).
- **핵심 기능 3개 & 이용 흐름**:
  1. **자연어 질의 기반 자율 Python 상권 데이터 마이닝**: 사장님이 "요즘 신림동 카페 매출이 왜 떨어졌지? 어떤 연령대를 노려야 해?"라고 물으면 에이전트가 서울시 상권 API 데이터를 가져와 스스로 Pandas 분석 코드를 짜고 실행해 "최근 분기 20대 오전 매출은 유지되나 30대 직장인 저녁 매출이 18% 감소함"과 같은 정확한 차트와 원인을 제시.
  2. **경쟁 밀집도 및 객단가 시뮬레이션**: 반경 500m 내 동종 업종 개·폐업 추이와 시간대별 유동인구 대비 점포당 추정 매출을 계산하여 런치/디너 세트 적정 가격대를 제안.
  3. **타겟 맞춤형 홍보 배너 및 지역 커뮤니티(당근 등) 발행 키트 생성**: 분석된 핵심 타겟(예: 관악구 20대 여성 1인가구)에 맞춰 스마트폰으로 대충 찍은 메뉴 사진을 보정하고 맞춤형 카피가 삽입된 프로모션 이미지를 즉석 생성.
  - **이용 흐름**: 내 가게 위치(관악/금천 상권 선택) 및 메뉴 사진 입력 → Data Interpreter 에이전트가 실시간 상권 API 호출 및 Python 코드 분석 실행 → 상권 진단 차트 및 타겟 전략 확인 → 원클릭으로 오늘의 타임세일 홍보 배너·문구 다운로드.

### 10. 위드유 노무VLM (WithYou Labor-VLM) — 외국인 유학생·이주노동자를 위한 다국어 근로계약서·급여명세서 VLM 판독 및 임금체불 진정 에이전트
- **주요 사용자**: 서울대·숭실대·중앙대 등 관악·동작권 외국인 유학생 아르바이트생 및 금천구·구로구(G밸리·독산동·가리봉동 일대) 제조·음식점 이주노동자.
- **문제**: 고용노동부 통계에 따르면 외국인 노동자 임금체불액은 가파르게 급증하여 **연간 약 1,500억 원대 규모**에 달하며, 피해는 주로 30인 미만 영세 제조업·건설업·음식숙박업에 집중되어 있다 (출처: 고용노동부 임금체불 현황 통계 https://www.moel.go.kr ). 그러나 언어 장벽과 한국 근로기준법(주휴수당, 야간근로수당, 최저임금 감액 금지 등)에 대한 무지로 인해 수기 근로계약서나 카카오톡 근무시간표를 가지고도 권리 구제를 받지 못한다.
- **왜 AI여야 하나**: 기존 번역기(파파고, 구글 번역)는 한국어로 적힌 수기 근로계약서나 급여명세서 글자만 기계적으로 번역할 뿐, **"수습기간 3개월간 최저임금의 90% 지급(단, 1년 미만 계약 시 불법)"**과 같은 한국 근로기준법 위반 여부나 카카오톡 출퇴근 캡처 화면을 합산한 미지급 주휴수당 금액을 계산해주지 못한다. **다국어 고해상도 VLM(Qwen2-VL)**과 **한국 노동법 Agentic RAG + 임금계산 도구호출**을 결합해야만 사진 촬영만으로 위법 조항 적출과 모국어 해설, 노동청 진정서 한국어 자동 작성이 가능해진다.
- **AI 적용 방식**: **다국어 Document VLM(계약서·근무표·카톡 캡처 파싱) + 국가법령정보센터 근로기준법 Agentic RAG + 수당 계산기 Function Calling + 양방향 번역(모국어 상담 ↔ 한국어 진정서)**.
  - 파이프라인: `[수기 근로계약서·급여명세서 사진 + 모국어(베트남어·중국어·우즈베크어·영어 등) 음성/텍스트 입력] → [Qwen2-VL/2.5-VL이 계약 조건 및 실제 근로시간 추출] → [Python 임금계산 도구호출로 최저임금·주휴수당 미지급액 산출 + 근로기준법 조항 RAG 매칭] → [모국어 법률 해설 리포트 + 고용노동부 제출용 한국어 임금체불 진정서 초안 생성]`
- **데이터/API**:
  1. 국가법령정보센터_근로기준법 및 최저임금법 현행 법령/판례 Open API: https://open.law.go.kr (접근 방법: 무료 Open API 신청, XML/JSON, 이용 조건: 공공누리 제1유형).
  2. 고용노동부_표준근로계약서(외국인근로자용 포함) 및 임금체불 진정 서식: https://www.moel.go.kr (공공저작물 자유 이용, 공공누리 제1유형).
  3. 법무부_외국인 유학생 시간제취업(아르바이트) 허용 기준 안내문: https://www.hikorea.go.kr (웹 공개 지침 텍스트 참조, 별도 Open API 유무: `"unknown"`).
- **핵심 기능 3개 & 이용 흐름**:
  1. **수기 근로계약서·출퇴근 기록표 VLM 위법 조항 스캐너**: 한국어를 전혀 몰라도 계약서 사진을 찍으면 VLM이 근로계약 기간, 시급, 휴게시간을 읽어들여 1년 미만 계약자의 수습 감액 위법, 주 15시간 이상 근무 시 주휴수당 누락 등 위법 사항을 모국어로 조목조목 짚어줌.
  2. **유학생 비자(D-2, D-4) 시간제취업 규정 위반 사전 예방 알림**: 외국인 유학생이 자칫 주당 허용 근무시간을 초과해 불법취업으로 불이익을 받지 않도록 TOPIK 급수 및 학기/방학 여부에 따른 합법 근로시간 한도를 함께 계산.
  3. **모국어 음성 진술 → 표준 한국어 '임금체불 진정서' 및 입증자료 패키지 자동 변환**: 피해 사실을 모국어 음성으로 말하면 AI가 육하원칙에 맞춘 공식 한국어 고용노동부 진정서 초안과 일자별 체불임금 산정 내역표를 PDF로 생성.
  - **이용 흐름**: 모국어 선택 후 근로계약서/급여명세서 사진 업로드 → VLM 파싱 및 임금 계산기 도구호출 → 미지급 임금 내역 및 위반 법조항 모국어 확인 → 모국어로 피해 경위 답변 → 한국어 노동청 진정서 PDF 및 서울외국인주민지원센터 상담용 요약본 다운로드.
- **하루 해커톤 MVP 범위**: 독소조항(10개월 계약인데 수습 10% 감액 및 주휴수당 미포함)이 적힌 한국어 근로계약서 샘플 이미지와 근무시간표를 업로드하고 베트남어/중국어/영어로 질문하면, 즉시 미지급 수당이 원 단위로 계산되고 근로기준법 제15조·최저임금법 제5조 근거와 함께 한국어 진정서 PDF가 출력되는 시연(추정: 9시간 내 구현 가능).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **고용노동부 노동포털 임금계산기**(https://labor.moel.go.kr ), **파파고 이미지 번역**(https://papago.naver.com ).
  - 차별점: 파파고는 계약서 텍스트만 번역할 뿐 법적 유불리를 알려주지 못하고, 노동포털은 한국어로 직접 숫자를 입력해야 한다. 본 서비스는 **비전 계약서 파싱 + 한국 노동법 추론 + 다국어↔한국어 행정서류 역변환**을 통합 제공한다.

### 11. 신스유저 랩 (SynthUser Lab) — 대학생·초기 창업팀을 위한 인구통계 기반 AI 합성 페르소나 집단(Synthetic Persona Swarm) 가상 시장검증 시뮬레이터
- **주요 사용자**: 서울대 앵커사업단·관악S밸리·금천청년꿈터 등에서 창업을 준비하거나 해커톤·캡스톤디자인을 수행하는 대학생 및 초기 스타트업 팀.
- **문제**: 중소벤처기업부와 창업진흥원의 《창업기업실태조사》(국가승인통계 제142016호) 등에 따르면 초기 창업기업은 자금 확보와 시장 개척(판로 및 초기 수요 검증)에 가장 큰 애로를 겪고 있으며, 자본이 부족한 청년·대학생 창업팀은 타겟 고객 인터뷰(FGI)나 UI 사용성 테스트에 수백만 원의 리서치 비용을 지출하기 어렵다 (출처: 창업진흥원 https://www.kised.or.kr , 국가통계포털 KOSIS https://kosis.kr ).
- **왜 AI여야 하나**: 기존 설문조사 폼이나 단순 단일 챗봇 프롬프팅("내 아이디어 어때?")은 AI 특유의 아첨 편향(Sycophancy Bias — 무조건 좋다고 칭찬하는 경향) 때문에 실제 시장의 냉정한 거절 반응을 재현하지 못한다. 2024~2025년 발전한 **합성 데이터/페르소나 정렬 생성 기술(Magpie, AgentInstruct)**과 **멀티에이전트 토론(Multi-Agent Debate) + GUI 시각 탐색**을 결합해야만, KOSIS 실제 인구·소득·소비 통계 분포에 기반한 서로 다른 성향의 가상 소비자 20명이 창업팀의 랜딩페이지나 기획안을 보고 날카로운 이탈 이유와 지불의사금액(WTP)을 시뮬레이션할 수 있다.
- **AI 적용 방식**: **통계청 분포 기반 합성 페르소나 생성(Magpie/AgentInstruct 응용) + 아첨 제거(Anti-Sycophancy) 멀티에이전트 그룹 인터뷰(FGI) + 랜딩페이지 VLM 시각 사용성 평가**.
  - 파이프라인: `[타겟 시장 설정(예: 관악구 거주 20대 자취생) + 서비스 기획서/UI 시안 입력] → [KOSIS 인구·소득·소비지출 통계 API 기반으로 현실적 제약조건(월 가처분소득 등)을 가진 10~20명의 이질적 페르소나 에이전트 생성] → [에이전트별 UI 시안 VLM 평가 및 멀티에이전트 FGI 찬반 토론] → [예상 이탈 지점 히트맵, 가격 민감도 곡선, 피벗 제안 리포트 생성]`
- **데이터/API**:
  1. 통계청_KOSIS 국가통계포털 Open API (연령별·지역별 인구, 가계동향조사 소득·소비지출 통계): https://kosis.kr/openapi/ (접근 방법: KOSIS 공유서비스 인증키 발급, REST/JSON, 이용 조건: 공공누리 제1유형).
  2. 서울특별시_서울서베이(도시정책지표조사) 및 청년통계 데이터: https://data.seoul.go.kr (서울열린데이터광장, 이용 조건: 공공누리 제1유형).
- **핵심 기능 3개 & 이용 흐름**:
  1. **KOSIS 실통계 앵커링(Statistical Anchoring) 합성 페르소나 군집 생성**: 막연한 가상 인물이 아니라 통계청 가계동향조사의 실제 소득 분위·월세 부담·소비 지출 제약을 부여받은 까다로운 잠재고객 페르소나 군집을 즉시 생성.
  2. **UI 프로토타입 VLM 첫인상 및 클릭 이탈 시뮬레이션**: Figma 캡처본이나 랜딩페이지 URL을 넣으면 각 페르소나 에이전트가 VLM으로 화면을 읽고 "가치 제안이 첫 화면에서 안 보임", "회원가입 버튼이 불안함" 등 지점별 이탈 사유를 핀포인트로 지적.
  3. **라이브 가상 FGI(초점집단면접) 토론방 및 압박 질문 개입**: 회의실 UI에서 5명의 합성 페르소나가 해당 서비스를 실제로 돈 내고 쓸지 서로 논쟁하며, 창업자가 중간에 새로운 가격 정책을 던지면 반응 변화를 실시간 관측.
  - **이용 흐름**: 타겟 고객군 조건 선택 및 서비스 기획서/UI 이미지 업로드 → KOSIS 통계 기반 10인의 페르소나 생성 → 가상 FGI 실시간 토론 및 UI 시각 피드백 관전 → 예상 전환율·적정 구독료·핵심 개선점 리포트 확인.
- **하루 해커톤 MVP 범위**: 해커톤 현장에서 **다른 참가팀의 아이디어 또는 심사위원이 즉석에서 제시한 서비스 아이디어와 화면 캡처**를 입력하면, KOSIS 통계 기반으로 생성된 5인의 까다로운 페르소나 에이전트가 화면 상에서 실시간 FGI 끝장 토론을 벌이고 지불의사금액과 UI 개선점을 도출하는 메타(Meta) 시연(추정: 9시간 내 구현 가능, 시연 몰입도 최상).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **오픈서베이**(https://www.opensurvey.co.kr ), **Synthetic Users**(해외 B2B SaaS, https://www.syntheticusers.com ).
  - 차별점: 오픈서베이는 문항당 수십~수백만 원의 비용과 수일의 시간이 걸리며, 해외 Synthetic Users는 한국 특화 통계(KOSIS, 서울시 1인가구 주거비 구조 등)가 반영되지 않고 화면 시각 평가(VLM UI Critique) 기능이 약하다.
- **관련 논문/근거 1~3개**:
  1. *Magpie: Alignment Data Synthesis from Scratch by Prompting Aligned LLMs with Nothing*, 2024 (ICLR 2025), `arXiv:2406.08464` (https://arxiv.org/abs/2406.08464 )

### 12. 사이언스그래프 VLM (ScienceGraph VLM) — 이공계 대학생·연구자를 위한 논문 수식·복합 도표 구조 파싱 및 재현 코드 자동 생성 에이전트
- **주요 사용자**: 서울대학교 및 전국 대학 학부연구생, 대학원생, R&D 엔지니어, 데이콘(DACON) 경진대회 참가자.
- **문제**: arXiv 등 학술 저장소에 매달 수만 건의 AI·이공계 논문이 쏟아지고 있으나, 대다수 논문이 다단 레이아웃, 복잡한 다층 표(Multi-level Table), 수식, 아키텍처 다이어그램으로 구성되어 있으며 코드가 미공개된 경우가 많아 학부생·초급 연구자가 논문의 핵심 수식을 코드로 재현하는 데 논문당 수일 이상이 소요된다(근거 통계 수치: 학부생 평균 논문 재현 소요시간 공식 국가통계는 `"unknown"`, 단 arXiv 월간 제출 논문 수는 https://arxiv.org/stats/monthly_submissions 에서 월 2만 건 이상으로 확인 가능).
- **왜 AI여야 하나**: 기존 PDF 텍스트 추출기(PyPDF, PDFMiner)는 2단 다단 논문에서 수식 첨자($x_{i,j}^{(t)}$)와 복잡한 성능 비교표의 행·열 구조를 완전히 깨뜨린다. 2024~2025년 등장한 **구조-인식-관계 삼중항 문서 파싱 모델(MonkeyOCR, mPLUG-DocOwl 1.5)**과 **코드 에이전트(SWE-agent 아키텍처)**를 결합해야만 논문 속 아키텍처 그림과 수식을 정확히 보존해 읽고, 실행 가능한 PyTorch 재현 코드와 인용 계보 그래프를 한 번에 생성할 수 있다.
- **AI 적용 방식**: **구조 보존형 Document VLM(MonkeyOCR / mPLUG-DocOwl 1.5 / Qwen2.5-VL) + 학술 인용 지식그래프(Semantic Scholar / OpenAlex API) + 코드 생성 및 문법 검증 샌드박스**.
  - 파이프라인: `[arXiv 논문 PDF 입력] → [Document VLM이 수식(LaTeX)·아키텍처 다이어그램·실험 표를 구조화 추출] → [OpenAlex/Semantic Scholar API로 선행·후속 핵심 논문 그래프 구축] → [수식-코드 1:1 매핑 PyTorch 모듈 생성 및 가상 입력 텐서(Dummy Tensor) Shape 테스트 자동 실행]`
- **데이터/API**:
  1. arXiv API 및 Open Access 논문 전문: https://info.arxiv.org/help/api/index.html (접근 방법: REST API 무료 호출, 이용 조건: 논문별 라이선스 CC BY 4.0 / CC BY-SA 등 메타데이터에 명시).
  2. OpenAlex API (전 세계 오픈 학술 논문·인용 그래프 DB): https://docs.openalex.org (접근 방법: 무료 REST API, API 키 불필요, 이용 조건: CC0 퍼블릭 도메인).
  3. Semantic Scholar Academic Graph API: https://www.semanticscholar.org/product/api (접근 방법: REST API, 이용 조건: 학술·비상업적 오픈 이용 가능).
- **핵심 기능 3개 & 이용 흐름**:
  1. **아키텍처 다이어그램 & 수식-코드 양방향 하이라이팅**: 논문 PDF의 특정 수식이나 블록 다이어그램 영역을 마우스로 드래그하면, VLM이 해당 시각 구조를 해석하여 대응하는 PyTorch `nn.Module` 클래스 코드를 생성하고 수식 변수와 코드 변수명을 1:1 색상 매칭.
  2. **자동 텐서 차원(Shape) 검증 루프**: 생성된 모델 코드가 단순 텍스트로 끝나지 않도록 백엔드 Python 샌드박스에서 더미 텐서(`torch.randn`)를 통과시켜 차원 불일치(RuntimeError)가 없을 때까지 에이전트가 자가 디버깅(Self-Debugging) 후 결과 반환.
  3. **실험 결과표(Table) 역추출 및 베이스라인 비교 차트화**: 논문 속 복잡한 다층 비교표를 JSON/DataFrame으로 무손실 변환하고 OpenAlex API를 통해 후속 논문들의 성능 추이를 인터랙티브 차트로 시각화.
  - **이용 흐름**: arXiv ID 또는 PDF 입력 → 논문 구조 파싱 및 인용 계보 그래프 생성 → 원하는 수식/다이어그램 박스 선택 → 자가 검증을 통과한 PyTorch 코드 및 Colab 노트북 다운로드.
- **하루 해커톤 MVP 범위**: 최신 2024~2025년 arXiv 논문 PDF를 입력받아 화면 좌측 PDF 뷰어에서 수식과 모델 구조도를 드래그하면, 우측에서 VLM이 이를 파싱해 PyTorch 코드를 짜고 실제 `torch` 더미 텐서 순전파(Forward Pass) 성공 로그까지 실시간 출력하는 데모(추정: 9시간 내 구현 가능).

  - 경쟁 서비스: **SciSpace (Typeset)**(https://typeset.io ), **ChatPDF**(https://www.chatpdf.com ), **Connected Papers**(https://www.connectedpapers.com ).
  - 차별점: SciSpace와 ChatPDF는 텍스트 요약·설명에만 그치고, Connected Papers는 인용 그래프만 보여준다. 본 서비스는 **시각적 다이어그램·수식 구조 파싱으로부터 실제 실행 검증된(Shape-Verified) PyTorch 코드까지 생성**한다.

### 13. 에코소트 VLM (EcoSort VLM) — 관악·금천 1인가구 밀집지역 다중 폐기물 객체 분할(SAM 2 + VLM) 및 자치구 조례 기반 배출·수거 자동화 에이전트
- **주요 사용자**: 분리배출 규정과 대형폐기물 스티커 발급 절차가 헷갈리는 관악구·금천구 1인가구 청년 및 다가구주택 거주민.
- **문제**: 환경부와 한국환경공단의 《전국 폐기물 발생 및 처리현황》 및 서울시 통계에 따르면, 배달용기·택배 증가로 1인당 생활계폐기물 및 플라스틱 발생량이 지속적 관리 대상이며, 특히 아파트와 달리 전담 관리인이 없는 다세대·원룸 밀집 지역(관악구 1인가구 비율 약 63%대)에서는 오염된 배달용기 혼합 배출과 대형폐기물 무단 방치로 인한 미관 훼손·과태료 분쟁이 심각하다 (출처: 환경부 환경통계포털 https://stat.me.go.kr , 자원순환정보시스템 https://www.recycling-info.or.kr , 관악구청 https://www.gwanak.go.kr ).
- **왜 AI여야 하나**: 기존 분리배출 안내 앱은 단일 품목("페트병")을 검색하거나 깨끗한 단일 물체 사진만 분류할 수 있을 뿐, **"고추장 양념이 묻은 플라스틱 배달용기 + 비닐 실링 + 알루미늄 호일 + 버려진 의자"**가 한데 섞여 있는 실제 자취방 분리수거함 사진을 찍었을 때 부위별 분리 방법과 자치구별 상이한 대형폐기물 수수료를 동시에 판정하지 못한다. 2024~2025년 발표된 **Segment Anything Model 2(SAM 2)** 및 **Open-Vocabulary Grounding VLM(Qwen2.5-VL)**을 결합해야만 한 장의 사진 속 복합 재질을 픽셀 단위로 분할하고 자치구 조례 수수료 API를 호출할 수 있다.
- **AI 적용 방식**: **다중 객체 분할·그라운딩(SAM 2 / Qwen2.5-VL) + 자치구별 배출 조례·대형폐기물 수수료 RAG/도구호출**.
  - 파이프라인: `[복합 쓰레기·폐가구 사진 촬영] → [SAM 2 + Qwen2.5-VL이 객체 및 세부 부위(몸통·뚜껑·라벨·오염도)를 바운딩박스/마스크로 분할 판독] → [거주 자치구(관악구/금천구) 분리배출 규정 및 대형폐기물 수수료 테이블 조회] → [객체별 배출 지침 오버레이 + 대형폐기물 예상 수수료 및 배출요일 안내]`
- **데이터/API**:
  1. 공공데이터포털_전국 대형폐기물 표준데이터 (관악구·금천구 등 지자체별 품목·규격·수수료 정보): https://www.data.go.kr (접근 방법: Open API 및 CSV 다운로드, 이용 조건: 공공누리 제1유형).
  2. 환경부_내 손안의 분리배출 가이드라인 공공데이터: https://www.me.go.kr / https://www.data.go.kr (이용 조건: 공공누리 제1유형).
  3. 서울특별시_자치구별 쓰레기 배출요일 및 수거시간 데이터: https://data.seoul.go.kr (서울열린데이터광장, 이용 조건: 공공누리 제1유형).
- **핵심 기능 3개 & 이용 흐름**:
  1. **복합 재질·오염도 동시 세그멘테이션 판독**: 배달 용기 더미 사진을 찍으면 화면 위 각 용기·뚜껑·비닐마다 마스크를 씌워 "뚜껑(PP: 세척 후 플라스틱)", "양념 베인 용기 바닥(세척 불가 시 종량제 봉투)"처럼 부위별 처방전을 이미지 위에 직접 표시.
  2. **폐가구 크기 추정 및 자치구별 대형폐기물 수수료 즉시 산출**: 버릴 의자나 행거 사진을 찍으면 주변 참조물 대비 규격을 추정해 관악구/금천구 대형폐기물 조례 기준 정확한 수수료(예: 회전의자 3,000원)와 신청 링크를 매칭.
  3. **동네(동별) 배출 요일·시간 알림 및 과태료 예방 체크**: 사용자 행정동(예: 관악구 청룡동, 금천구 가산동)의 일반·음식물·재활용품 배출 가능 요일과 시간을 대조해 "오늘 저녁 8시 이후 배출 가능 여부"를 즉시 안내.
  - **이용 흐름**: 자취방 쓰레기/폐가구 촬영 → SAM 2 + VLM 부위별 분할 및 오염도 판독 → 화면 위 컬러 마스크별 분리배출 방법 확인 → 대형폐기물 포함 시 수수료 확인 및 배출 신고 페이지 연결.
- **하루 해커톤 MVP 범위**: 해커톤 현장에서 배달 용기, 라벨 붙은 페트병, 소형 가구/소품 여러 개를 책상 위에 올려놓고 웹캠/스마트폰으로 찍으면, 즉시 객체별 바운딩박스/세그멘테이션 마스크가 씌워지며 각 부위별 재질·배출 방법과 관악구·금천구 기준 대형폐기물 수수료가 출력되는 실시간 비전 데모(추정: 9시간 내 구현 가능).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **내 손안의 분리배출**(환경부·한국환경공단 앱), **빼기**(대형폐기물 수거 앱, https://bbegi.com ).
  - 차별점: '내 손안의 분리배출'은 텍스트 검색 위주이며, '빼기'는 대형폐기물 단일 품목 수거에 집중한다. 본 서비스는 **다중 물체·오염 상태까지 한 번에 분할 판독(Multi-Object Grounding)하고 자치구별 세칙과 대형폐기물 수수료를 통합 안내**한다.
- **관련 논문/근거 1~3개**:

### 14. 히어링브릿지 옴니 (HearingBridge Omni) — 청각장애인·노인성 난청인을 위한 비언어 환경음·음성 통합 인지(Audio-LLM) 및 한국수어 글로스 변환 플랫폼
- **주요 사용자**: 관공서 창구, 대학 강의실, 다중이용시설 및 1인가구 주거지에서 생활하는 청각장애인 및 고령 난청인.
- **문제**: 보건복지부 《등록장애인 현황 통계》(2025년 말 기준)에 따르면 전체 등록장애인(2,627,761명) 중 **청각장애인은 17.1%로 지체장애에 이어 두 번째로 많은 비중**을 차지하며, 특히 한 해 동안 **새로 등록된 장애인(82,900명) 중 청각장애인이 30.6%로 1위(65세 이상 고령 신규 장애인 중에서는 무려 46.3%)**를 차지할 만큼 급증하고 있다 (출처: 보건복지부 등록장애인 현황 통계 https://www.mohw.go.kr ). 그러나 기존 자막 도구는 사람의 말소리(STT)만 텍스트로 바꿀 뿐, 화재경보음·인터폰·아이 울음소리·화자의 다급한 감정 억양 등 **비언어적 오디오 맥락(Paralinguistic & Environmental Audio)**을 전달하지 못하며, 선천적 농인에게는 긴 한국어 문장보다 한국수어(KSL) 문법 체계가 훨씬 직관적이다.
- **왜 AI여야 하나**: 기존 음성인식(Whisper 등 단순 ASR)은 오디오에서 텍스트만 추출하면서 사이렌 소리, 유리 깨지는 소리, 화자의 분노/긴급 억양 정보를 모두 버린다. 2024~2025년 등장한 **네이티브 오디오-언어 통합 모델(Qwen2-Audio, Mini-Omni2)**을 활용해야만 단일 모델 내에서 **환경음(Audio Event) + 음성 감정(Paralinguistics) + 발화 내용(Speech)**을 동시에 이해하고, 이를 한국수어 어순(Gloss)과 시각적 긴급도 UI로 실시간 변환할 수 있다.
- **AI 적용 방식**: **통합 오디오 파운데이션 모델(Qwen2-Audio / Mini-Omni2) + 한국수어(KSL) 사전 매핑 글로스 변환 에이전트**.
  - 파이프라인: `[실시간 마이크 오디오 스트림 입력] → [Qwen2-Audio가 배경 환경음(사이렌·초인종) + 화자 감정/긴급도 + 발화 텍스트를 동시 추론] → [긴급 환경음 감지 시 화면 전체 색상 점멸 알림 + 발화 문장을 한국수어 문법 어순(KSL Gloss) 및 국립국어원 수어 영상 클립으로 실시간 매칭 재생]`
- **데이터/API**:
  1. 국립국어원_한국수어사전 공공데이터 / 문화포털 수어 영상 Open API: https://sldict.korean.go.kr / https://www.data.go.kr (공공데이터포털, 일상어·전문용어 수어 동영상 및 이미지 URL 제공, 이용 조건: 공공누리 제1유형).
  2. Qwen2-Audio 오픈소스 모델 가중치: https://github.com/QwenLM/Qwen2-Audio (접근 방법: Hugging Face 다운로드, 이용 조건: Apache-2.0 License).
  3. AI-Hub 한국수어 번역 데이터셋 및 도시 소음 데이터셋(참조용): https://www.aihub.or.kr (이용 조건: AI-Hub 이용 약관 준수).
- **핵심 기능 3개 & 이용 흐름**:
  1. **비언어 환경음 + 화자 감정 억양 통합 시각 레이더**: 단순 자막 옆에 `[🚨 배경음: 화재경보기 벨소리 감지 - 매우 위급]`, `[🗣️ 화자 톤: 매우 빠르고 다급한 목소리]`와 같이 소리의 맥락과 방향·긴급도를 시각적 배지와 화면 테두리 점멸로 표현.
  2. **한국어 문장 → 한국수어 글로스(KSL Gloss) 변환 및 수어 사전 영상 시퀀스 재생**: 문해력이 낮거나 수어가 제1언어인 농인을 위해 한국어 조사를 제거하고 수어 어순으로 재배열한 뒤, 국립국어원 한국수어사전 API의 단어별 수어 영상을 연속 재생.
  3. **관공서·병원 창구 양방향 원터치 응답 보드**: 상대방의 질문을 수어/시각 자막으로 확인한 뒤, 농인이 화면의 맥락별 추천 답변 버튼을 누르거나 수어 단어를 선택하면 자연스러운 한국어 음성(TTS)으로 창구 직원에게 대신 말해줌.
  - **이용 흐름**: 앱 실행 및 실시간 오디오 감지 시작 → 배경 위험음·호출음 발생 시 즉각 시각·진동 경보 → 상대방 발화 시 감정 톤이 반영된 자막 및 한국수어 영상 시퀀스 확인 → 추천 응답 터치로 음성 답변 송출.
- **하루 해커톤 MVP 범위**: 해커톤 발표 현장에서 사이렌/초인종 소리와 함께 다급한 목소리로 안내 방송을 들려주면, `Qwen2-Audio`가 배경 환경음 종류와 화자의 긴급 감정, 발화 내용을 동시에 분석해 화면에 경보를 띄우고, 핵심 어휘에 해당하는 국립국어원 한국수어사전 영상을 실시간 매칭해 재생하는 시연(추정: 9시간 내 구현 가능).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **소보로(Sovoro)**(https://www.sovoro.kr ), **구글 라이브 트랜스크라이브(Live Transcribe)**.
  - 차별점: 기존 문자통역 서비스는 텍스트 변환(ASR)에만 집중해 화자의 감정 톤이나 복합 환경음 맥락을 결합해 추론하지 못하며, 국립국어원 수어 영상과의 실시간 글로스 브릿지 기능이 없다.
- **관련 논문/근거 1~3개**:
  1. *Qwen2-Audio Technical Report*, 2024, `arXiv:2407.10759` (https://arxiv.org/abs/2407.10759 )
  2. *Mini-Omni2: Towards Open-source GPT-4o with Vision, Speech and Duplex Capabilities*, 2024, `arXiv:2410.11190` (https://arxiv.org/abs/2410.11190 )
- **리스크**:
  - **안전 리스크**: 화재경보 등 생명 직결 알람의 오탐/미탐 위험 → 데시벨(dB) 및 주파수 피크 감지 규칙 알고리즘을 1차 트리거로 두고 Audio-LLM이 2차 정밀 분류하는 하이브리드 구조 채택.
- **자체 점수(1~5)**: 문제심각도 **5** / AI필연성 **5** / 구현가능성 **4** / 데이터확보 **5** / 차별성 **5** / 시연임팩트 **5**

### 15. 골든타임 옴니 (GoldenTime Omni) — 야간·1인가구 응급상황 시 실시간 영상·음성 중증도 사전분류(Pre-Triage) 및 가용 응급병상 매칭 에이전트
- **주요 사용자**: 심야 시간대 갑작스러운 증상(흉통, 호흡곤란, 화상, 소아 고열·경련 등)을 겪는 관악·금천 1인가구 청년, 영유아 부모 및 독거노인.
- **문제**: 응급실 과밀화와 전문의 부족으로 인해 환자가 수용 가능한 병원을 찾지 못해 헤매는 '응급실 미수용(재이송)' 및 골든타임 지연 문제가 사회적 재난 수준으로 대두되고 있으며, 반대로 경증 환자가 권역응급의료센터로 몰려 중증 환자 처치가 지연되는 악순환이 반복되고 있다 (출처: 국립중앙의료원 중앙응급의료센터 응급의료 통계연보 https://www.e-gen.or.kr , 소방청 119구급서비스 통계연보 https://www.nfa.go.kr — 단, 소방청의 세부 재이송 원천 건수 API는 별도 분리 개방되지 않아 세부 수치는 `"unknown"`).
- **왜 AI여야 하나**: 당황한 환자나 보호자는 텍스트 챗봇에 증상을 차분히 타이핑할 수 없으며, 전국 수십 개 응급실 중 현재 **'내 증상에 필요한 특정 처치(예: 소아 응급내시경, 뇌경색 재관류술, 화상 처치)'가 지금 당장 가능한 병상**이 어디에 몇 개 남았는지 일반인이 테이블을 읽고 판단하기 불가능하다. 2024~2025년 등장한 **사고하며 말하는 실시간 멀티모달 추론 모델(Mini-Omni-Reasoner / Freeze-Omni)**과 **중앙응급의료센터 실시간 가용병상 Open API 도구호출**을 결합해야만, 카메라로 환부/상태를 비추며 말로 대화하는 동시에 한국형 응급환자 분류도구(KTAS) 기준 사전 질문과 수용 가능 병원 매칭을 30초 내에 끝낼 수 있다.
- **AI 적용 방식**: **실시간 비전-음성 멀티모달 추론(Mini-Omni2 / Mini-Omni-Reasoner 아키텍처 응용) + KTAS 기반 문진 프로토콜 RAG + 국립중앙의료원 실시간 응급실 가용병상 Open API 도구호출**.
  - 파이프라인: `[환자/보호자 실시간 음성 및 카메라 영상(환부·호흡상태) 입력] → [멀티모달 에이전트가 시각·청각 징후 확인 및 KTAS 기준 핵심 감별 질문 음성 수행] → [국립중앙의료원 실시간 가용병상·중증질환 수용가능 API(`ErmctInfoInqireService`) 호출] → [수용 가능 최단거리 응급실/달빛어린이병원 매칭 + 119 구급대원 인계용 브리핑 카드 생성]`
- **데이터/API**:
  1. 국립중앙의료원_전국 응급의료기관 정보 조회 서비스 (`ErmctInfoInqireService` — 실시간 가용병상 `getEmrrmRltmUsefulSckbdInfoInqire`, 중증질환 수용가능 정보 등): https://www.data.go.kr (공공데이터포털 Open API, REST/XML·JSON, 활용신청 즉시 승인, 이용 조건: 공공누리 제1유형).
  2. 국립중앙의료원_전국 병·의원 및 약국 찾기 서비스 (야간·휴일 진료 달빛어린이병원 및 당직 의료기관 조회): https://www.data.go.kr (공공데이터포털 Open API, 이용 조건: 공공누리 제1유형).
  3. 보건복지부·대한응급의학회_한국형 응급환자 분류도구(KTAS) 공개 지침 및 국민 응급처치 표준 가이드라인: https://www.e-gen.or.kr (공공 가이드라인 문서 참조, 별도 KTAS API 유무: `"unknown"`).
- **핵심 기능 3개 & 이용 흐름**:
  1. **핸즈프리(Hands-Free) 영상·음성 응급 문진 및 응급처치 코칭**: 손을 쓰기 힘든 응급 상황에서 카메라로 화상 부위나 환자 상태를 비추고 말하면 AI가 즉시 지혈·화상 냉각·하임리히법 등 보건복지부 표준 응급처치를 음성으로 지시하며 레드플래그(Red Flag) 징후를 체크.
  2. **국립중앙의료원 API 연동 '실시간 가용병상 + 필수 처치 가능 여부' 교차 매칭**: 단순 거리순 나열이 아니라, 현재 환자 증상에 필요한 장비·당직의(예: CT 촬영 가능 여부, 소아 중환자실 잔여 병상, 응급실 일반 병상 수)가 실시간으로 열려 있는 관악·금천·인근 권역 병원만 필터링해 안내.
  3. **119 구급대원·응급실 예진 간호사 인계용 '30초 패스트트랙 요약본' 생성**: 통화·문진 중 파악된 증상 발현 시각(Onset), 기저질환, 복용 약물, 추정 중증도를 표준 의무기록 요약 포맷(SBAR)과 QR코드로 생성해 구급대원 도착 시 즉시 제시.
  - **이용 흐름**: 응급 모드 실행(음성+카메라 활성화) → 실시간 음성 문진 및 응급처치 가이드 수행 → 백그라운드에서 국립중앙의료원 실시간 가용병상 API 호출 → 수용 가능한 최적 병원 Top 3(병상 수·직통전화) 확인 및 119 브리핑 카드 띄우기.
- **하루 해커톤 MVP 범위**: 모의 응급 상황(예: 자취방에서 뜨거운 물에 데인 화상 시나리오 또는 갑작스러운 흉통 시나리오)을 웹캠과 음성으로 시연하면, 멀티모달 에이전트가 실시간 음성으로 응급처치를 코칭하는 동시에 공공데이터포털 `국립중앙의료원_전국 응급의료기관 정보 조회 서비스` API를 실제로 호출하여 현재 시각 기준 서울 관악·금천·동작·구로 인근 응급실의 실시간 잔여 병상 수와 수용 가능 여부를 지도 위에 띄우고 119 SBAR 인계 카드를 생성하는 라이브 데모(추정: 9시간 내 구현 가능).
- **경쟁·유사 서비스와 차별점**:
  - 경쟁 서비스: **응급의료정보제공(E-Gen) 앱**(국립중앙의료원, https://www.e-gen.or.kr ), **굿닥**(https://www.goodoc.co.kr ).
  - 차별점: E-Gen 앱은 당황한 환자가 복잡한 의료 용어(뇌경색 재관류, 복부외상 등) 체크박스를 직접 선택해 검색해야 한다. 본 서비스는 **환자의 실시간 음성·영상 증상 표현으로부터 필요한 응급실 처치 항목을 AI가 역추론하여 실시간 가용병상 API와 자동 매칭**한다.
- **관련 논문/근거 1~3개**:
