# D003 이사 지킴이 제작 계획 판정

**결론: 설치 없는 모바일 웹으로, "계약금 보내기 전에" 쓰는 확인 도구를 만든다.** 사용자가 올린 방 사진과 이미 받은 견적서를 AI가 읽어 초안을 만들고, 사용자가 고친 뒤, 정해진 규칙이 대조해 **추가요금으로 이어질 수 있는 미확인 사항**을 찾아 업체에 보낼 확인 문구로 바꾼다. 추가요금을 "막는다"고 약속하지 않고, "계약 전에 무엇을 확인해야 하는지 구체화한다"고 말한다.

## 확정 범위 (P0 — 1인이어도 11/27 하루에 완주할 범위)
1. **입력**: 방 사진 1~3장 · 견적서 이미지(JPEG/PNG) 1장 · 출발·도착지 작업조건(층수·엘리베이터·사다리차·주차거리·분해설치)
2. **사용자 확인**: AI 초안(품목·수량·사진 번호 / 총액·차량·인원·장비·포함 문구·원문 발췌)을 원문 옆에서 고친다
3. **대조**: 결과를 `명시됨 / 포함 여부 미확인 / 조건 모호 / 판독 불가` 네 가지로만 표시. 확인 규칙 3개
   - ① 짐 품목의 포함 여부 ② 작업조건·차량·인원·장비의 기재 여부 ③ 추가비 발생 조건 확인 질문
   - 표준약관 제4조·제5조 제3항·제8조 제2·3항은 **변경 원인·사전 고지 요건을 생략하지 않은 참고 안내**로만 연결
4. **확인 요청**: 검토한 문장 틀에 항목을 넣어 복사. 같은 결과 화면에 근거(사진·견적 발췌·참고 조항)를 함께 보여 준다

- **AI 호출은 2번, 병렬**(방 사진 → 품목 / 견적서 → 항목). 대조·문구는 LLM 없이 규칙과 문장 틀로 처리 → 없는 조항·"위법" 단정이 나올 수 없다
- 기술: Next.js 단일 코드베이스 + 이미지 입력 모델 어댑터 1개 + 서버 무저장. 사진은 브라우저에서 줄여 올린다(Vercel 요청 4.5MB 한도)

## 제외
- P1: 별도 당일 대응 화면·저장·재열람, 업체 답변 첨부·재점검, 공유 링크, 영상, PDF, 출발 전 물품 상태 사진 첨부
- P2: 다중 견적 비교, 전자서명, 업체 매칭, 임대차 흠집·보증금
- 하지 않는 것: 위법·배상액·취소 위약금 자동 계산, 견적→계약 증액 비교(문서 1장으로는 불가), 사진으로 부피·톤수 산정

## 근거 수치 (기획서용, 원문 확인: `wiki/sources/kca2026-소규모이사-피해.md`)
- 이사 피해구제 신청 2023년 603 → 2024년 785 → 2025년 961건
- 2025년 소규모 이사(10만~100만 원) 241건 중 20~30대 65.1%(157건), 20대 22.8%로 전체 이사 이용자의 20대 비율 11.6%의 약 2배
- 피해 유형(중복 집계 281건): 물품 파손·분실 47.7%, **추가 비용 요구 24.9%(70건)**, 이사거부/계약불이행 13.9% — 241건을 분모로 쓰지 않는다
- 소비자원 원문: 추가비용 거부 → 업체의 계약불이행으로 이어지는 사례가 많고, 비대면 계약이라 더 취약

## 차별점 문장 (Astra 최종안 채택)
> 기존 Agoyu·Yembo는 공개 소개상 짐 조사와 견적·확인·분쟁 지원까지 제공하며, 우리는 소비자가 이미 받은 외부 견적서를 자신의 짐 사진·작업조건과 대조해 한국 이사화물 표준약관을 참고한 확인 요청으로 바꾸는 데 집중합니다.

"국내 최초", "기존은 견적만", "경쟁 없음"은 쓰지 않는다. 경쟁사의 외부 견적 대조 기능 유무는 unknown.

## 남은 반대 의견
- 없음(세 쟁점 합의). 단 Argon이 예상한 "규칙과 사람 확인을 앞세우면 'AI 서비스냐'는 질문을 받는다"는 위험은 남는다 → 발표에서 **비정형 사진·견적서를 구조화하는 것이 AI의 몫**이고, 판정을 규칙으로 통제하는 것이 설계 의도라고 설명한다.

## 남은 unknown
- 본선 사전 코딩·준비물 허용 범위 → 11/26 멘토링에서 질의
- 공정위 표준약관(제10035호) 원본 전문 대조 미완료 → 제출 전까지는 "법제처 생활법령 설명 기준"으로 표기
- 경쟁사의 외부 견적서 대조 기능 유무, 이용·지불 의사
- 한국어 이사 견적서에 대한 모델 인식 정확도, iOS Safari 실기기 촬영·HEIC 동작
