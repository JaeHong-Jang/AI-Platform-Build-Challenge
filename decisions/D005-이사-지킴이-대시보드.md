# D005 이사 지킴이 대시보드·Ollama 에이전트 판정

**결론: 모바일 단계형 화면(D004)을 버리고, 사용자의 기존 공모전 사이트 구조(맛대패스 레일·상단바·KPI)를 따른 대시보드로 전환한다. AI는 로컬 Ollama로 돌린다.**

- **사용자 결정**: 색상 A안 '통과증 티일'(맛대패스 slate+teal, 상태 대비 6.8~9.5), 입력은 붙여넣기·직접 입력(Ollama 모델이 모두 텍스트 전용)
- **화면**: 한눈에(결론 문장·KPI 4·대조표·근거) + 오른쪽 문의 패널(확인 요청 → 답변 점검 에이전트 → 남은 것만 재문의) / 견적·짐 입력 / 참고 조항·통계 / 에이전트 기록. Pretendard, lucide, 다크 모드
- **AI**: 견적서 글 → 항목 `ax4-light`(JSON 스키마 출력), 업체 답변 점검 에이전트 `qwen3:4b-instruct`(도구 호출). qwen2.5:7b는 도구 결과 다음 턴에서 3/3 실패해 제외 (`runs/out/b007-ollama.sonnet.md`)
- **정확도 장치**: 원문에 없는 발췌·숫자·사다리차 언급은 코드가 버림(실측 환각 2건 근거), '명시됨'은 금액·별도·조건·거절 표현이 없을 때만, 이미 명시된 항목은 상충(conflicting)으로만 뒤집기, 후보는 기본 미선택·개별 승인, 입력이 바뀌면 승인과 '답변 반영'이 함께 풀림
- **검증**: 단위 테스트 22/22, `tsc`, `next build`, 실제 Ollama로 가상 사례 전 흐름 브라우저 완주(읽기 7~13초·점검 9~11초·오류 0), Ollama 꺼짐 시 미리 만든 초안으로 대체 + 화면 표시

## 남은 반대 의견·unknown
- qwen3:4b는 "짐 많으면 추가 나올 수 있습니다"를 추가비 카드에 연결하지 못함(3회 실측 모두). 확인 안 된 채로 재문의 목록에 남는 안전한 실패지만 재현율은 개선 과제
- 표본은 가상 사례 1개 — 40개 합성 평가셋(Sol 제안)으로 오판정률을 측정해야 함
- 사진 입력 없음(비전 모델 미설치), 다중 견적 비교 없음(P2)
- 요청 스트림 사전 크기 제한, WSL 게이트웨이 실패 시 127.0.0.1 재시도는 미구현(Argon 낮음)
