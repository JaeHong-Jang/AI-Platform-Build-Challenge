## 공통 규칙
- 사실(통계·논문·데이터셋·API·경쟁 서비스)은 반드시 URL/DOI/arXiv ID와 함께 제시한다. 확인하지 못한 값은 "unknown"이라고 쓴다. 지어내지 않는다.
- 추정과 사실을 구분해 표시한다 ("추정:" 접두어).
- 한국어로 답한다. 고유명사·논문 제목은 원문 유지.
- 파일을 수정하지 말고 최종 답변만 출력한다.

# 과제 B005 · 분석 (실무팀) — 제작 계획서 (딥리서치 기반)
선택된 아이디어: **이삿날 "이건 추가요" 없게.** 먼저 두 조사 파일을 직접 열어 모두 읽어라.
- `runs/out/b005-evidence.sol.md` — 피해 통계·이사화물 표준약관·분쟁 원인·정책
- `runs/out/b005-benchmark.sonnet.md` — 국내외 경쟁 서비스(Agoyu·Yembo·미소·짐싸 등)와 판정: "짐 목록 자동 생성은 흔함 → 차별점은 **내가 받은 견적서를 내 짐 사진과 대조해 이삿날 추가요금이 나올 자리를 계약 전에 문구로 막는 소비자 편 도구**"
팀 조건: 대학생 1~3명, **강점은 웹·앱 개발**, AI는 API 사용(모델 학습 없음). 일정: 기획서 10/25, 준비 11/2~11/25, **본선 11/27 09~18시 하루 구현**.

웹 검색으로 필요한 근거를 직접 더 찾아 보강하라(기술 성능·브라우저 지원·약관 원문·논문). 모든 사실에 출처 URL, 확인 못 하면 unknown, 추정은 "추정:".

## 계획서 목차 (모두 채운다)
1. **한 줄 정의와 차별점** — 기존 서비스(이름) 대비 "기존 A는 ○○까지, 우리는 ●●" (검증 수준을 넘지 않게)
2. **사용자와 사용 순간** — 주 사용자, 언제 여는가 (견적 받을 때 / 계약 직전 / 이사 당일 / 입주 후)
3. **핵심 기능 (우선순위 P0/P1/P2)** — 각 기능의 입력→처리→출력. 예: 방 사진·영상→짐 목록 / 견적서·계약서 사진→항목 추출 / 대조→누락·모호 항목 / 업체에 보낼 확정 문구(표준약관 근거) / 당일 추가요금 요구 시 근거 카드 / (검토) 입주·퇴거 흠집 사진 기록 결합 여부와 이유
4. **AI가 하는 일 vs 규칙이 하는 일 vs 사람이 확인하는 일** — 표로
5. **웹 vs 앱 결정** — 후보: 모바일 웹/PWA, 네이티브 앱, 하이브리드(React Native/Flutter). 기준: 카메라·영상 촬영과 업로드(iOS Safari 포함 브라우저 지원 근거), 이사 당일 현장 사용, 업체와 링크 공유, 설치 장벽, 팀의 웹 강점, 9시간 구현, 심사 시연. **결론과 근거 URL**
6. **기술 구조** — 프런트·백엔드·저장소·AI API(이미지 물체 인식/VLM, 문서 OCR, LLM) 후보와 선택 이유, 데이터 흐름 그림(텍스트), 개인정보(집 내부 사진) 처리 원칙
7. **기술 근거** — VLM/물체 인식으로 가구·가전 식별이 얼마나 되는지(논문·벤치마크·공식 문서), 부피·개수 추정의 한계와 우회(사용자 확인 단계), 문서 OCR 성능
8. **규칙 데이터** — 이사화물 표준약관·소비자분쟁해결기준에서 규칙으로 만들 조항 목록(조항 번호·원문 요지·URL), 짐 부피·톤수 참고 기준이 공식적으로 있는지
9. **평가 방법과 성공 지표** — 직접 만든 방 사진·견적서 세트로 무엇을 몇 개 재나 (누락 탐지율, 오탐, 처리 시간)
10. **3분 시연 시나리오** — 초 단위
11. **일정** — 10/25 기획서까지 / 11/2~11/25 준비 / **11/27 당일 시간표(09~18시, 1시간 단위)** / 1·2·3인 역할 분담
12. **위험과 대응** — 정확도·법적 표현(법률 자문 아님)·개인정보·업체 반발·경쟁 확장
