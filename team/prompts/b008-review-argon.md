# 과제 B008 · 지휘부 검증 (당신: argon, 지휘부 — 기술·구현 관점)
**셸 명령(command)은 쓸 수 없다. 파일 읽기 도구만 쓴다.**
사용자 요구: 조건 입력 → 맞춤 홈, 에이전트(오케스트레이터 1 + 3팀×3)가 실시간으로 이삿짐을 옮기는 장면(새로 그리는 SVG)과 서류 산정, 왼쪽 레일 에이전트 켜기/끄기, 온톨로지 근거 그래프, 선택 부담 완화, 업체를 정해 두지 않고 고르는 기능, TRITON 디자인 참고. 단, 해결하는 문제는 그대로(계약 전 견적 빈칸 → 이삿날 추가요금).
근거 문서: `decisions/D006-이사-지킴이-에이전트-관제.draft.md`(판정 초안, 주장 K1~K11), `briefs/B008-이사-지킴이-에이전트-관제.md`(사용자 요구 원문과 정정 2건), `runs/out/b008-design.sonnet.md`(채택 기반안), `runs/out/b008-design.sol.md`(독립안), `runs/out/b008-data.sol.md` + `runs/out/b008-data-peer.sonnet.md`(근거 자료와 상호 검증), `runs/out/b008-triton.sonnet.md`(TRITON 구조), `runs/out/b008-palette.sonnet.md`(A안 사용자 선택), 현재 코드 `web/src/lib/*.ts`, `decisions/D005-이사-지킴이-대시보드.md`.
다른 지휘부 위원의 검토는 보지 않는다(블라인드).
출력: K1~K11 각각 **찬성/반대/보류** + 이유(파일:줄 또는 URL), 그다음 초안에 없는 치명적 문제 TOP 5(재현 가능하게), 마지막에 조건부 승인 조건.
특히 볼 것: 로컬 Ollama(8GB GPU, ax4-light 7B + qwen3:4b) 직렬 대기열·모델 교대·취소 토큰 설계의 구현 가능성, 조건 해석을 ax4-light로 하는 판단(JSON 스키마·환각 차단), 장면-카드 이벤트 동기화가 Next 16/React 19 클라이언트에서 어긋나지 않는 구조인지, 1,300~1,500줄 장면의 일정 위험과 줄이는 방법, CaseState v2→v3 이전과 기존 22개 시험 회귀, 토글이 정확도 검증기를 우회할 경로가 있는지, 관악구 CSV를 앱에 넣는 방식(빌드 시 정적 포함 vs API, 개인정보 열 제거).
