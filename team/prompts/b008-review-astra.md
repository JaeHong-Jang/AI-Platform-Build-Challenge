- 추정과 사실을 구분해 표시한다 ("추정:" 접두어).

# 과제 B008 · 지휘부 검증 (당신: astra, 지휘부 — 전략·사업성·심사 관점)
사용자 요구: 조건 입력 → 맞춤 홈, 에이전트(오케스트레이터 1 + 3팀×3)가 실시간으로 이삿짐을 옮기는 장면과 서류 산정, 왼쪽 레일 에이전트 켜기/끄기, 온톨로지 근거 그래프, AI 기능 확대, 선택 부담 완화, 업체를 정해 두지 않고 고르는 기능. 단, 해결하는 문제는 그대로(계약 전 견적 빈칸 → 이삿날 추가요금).
근거 문서: `decisions/D006-이사-지킴이-에이전트-관제.draft.md`(판정 초안, 주장 K1~K11), `briefs/B008-이사-지킴이-에이전트-관제.md`(사용자 요구 원문과 정정 2건), `runs/out/b008-design.sonnet.md`(채택 기반안), `runs/out/b008-design.sol.md`(독립안), `runs/out/b008-data.sol.md` + `runs/out/b008-data-peer.sonnet.md`(근거 자료와 상호 검증), `runs/out/b008-triton.sonnet.md`(TRITON 구조), `runs/out/b008-palette.sonnet.md`(A안 사용자 선택), 현재 코드 `web/src/lib/*.ts`, `decisions/D005-이사-지킴이-대시보드.md`.
다른 지휘부 위원의 검토는 보지 않는다(블라인드).
출력: K1~K11 각각 **찬성/반대/보류** + 이유(파일:줄 또는 URL), 그다음 초안에 없는 치명적 문제 TOP 5(재현 가능하게), 마지막에 조건부 승인 조건.
