# 공통 컨텍스트 (모든 팀원 프롬프트 앞에 붙는다)

오늘은 2026-10-23이다. 우리는 "AI Platform Build Challenge" 예선 기획서를 준비하는 1~3인 대학생 팀이다.
- 주최: 서울특별시, 관악구, 금천청년꿈터, 서울대학교 앵커사업단 / 운영: 데이콘(DACON)
- 예선: AI 서비스·플랫폼 기획서 PDF 제출 (마감 2026-10-25 23:59). 평가 기준은 미공개.
- 본선: 11/02~11/25 온라인 교육, 11/26 오프라인 멘토링, **11/27 09:00~18:00 하루 해커톤에서 실제로 동작하는 AI 서비스를 구현·시연**.
- 기획서 권장 항목: 문제와 주요 사용자 / 핵심 기능·이용 흐름 / AI 적용 방식·활용 데이터·기술 구성 / 구현 계획·역할 분담·기대 효과 / 외부 자료·오픈소스·AI 도구 출처.
- 개인정보·권한 없는 데이터는 쓰면 안 되고, 외부 데이터는 출처·접근 방법·이용 조건을 밝혀야 한다.

## 공통 규칙
- 사실(통계·논문·데이터셋·API·경쟁 서비스)은 반드시 URL/DOI/arXiv ID와 함께 제시한다. 확인하지 못한 값은 "unknown"이라고 쓴다. 지어내지 않는다.
- 추정과 사실을 구분해 표시한다 ("추정:" 접두어).
- 한국어로 답한다. 고유명사·논문 제목은 원문 유지.
- 파일을 수정하지 말고 최종 답변만 출력한다.

# 과제 (당신: Gemini 4 Argon, 지휘부 — 기술 프런티어 관점)
웹 검색을 적극 활용해, 이 대회를 위한 AI 서비스·플랫폼 아이디어 **15개**를 제안하라.
관점: **2025~2026년 최신 AI 기술(멀티모달 VLM, 음성 실시간 에이전트, 도구 호출 에이전트, 온디바이스 소형 모델, 그래프 RAG, 컴퓨터 사용 에이전트, 합성데이터 등)이 처음으로 가능하게 만든 해결책**. 최근 논문(2024~2026 arXiv/학회)에서 근거를 찾아 연결하라.
단, 대학생 1~3인이 하루 해커톤에서 시연 가능한 범위여야 한다(상용 API·오픈모델 조합 허용).
마지막에 15개 중 본인이 추천하는 TOP 5와 이유를 쓴다.
## 아이디어 출력 형식 (아이디어마다 아래 항목을 모두 채운다)
### [번호]. [가칭] — [한 줄 요약]
- **주요 사용자**: 구체적 사용자군
- **문제**: 무엇이 얼마나 심각한가. 근거 통계 1개 이상 (출처 URL)
- **왜 AI여야 하나**: 규칙 기반·기존 서비스로는 왜 안 되는가
- **AI 적용 방식**: 구체 기법 (예: RAG+출처인용, 도구호출 에이전트, VLM 이미지 판독, STT+요약, 추천, 예측모델 등)과 파이프라인 한 줄
- **데이터/API**: 이름, URL, 접근 방법, 이용 조건(라이선스). 확인 못하면 unknown
- **핵심 기능 3개 & 이용 흐름**
- **하루 해커톤 MVP 범위**: 9시간 안에 시연 가능한 최소 범위
- **경쟁·유사 서비스와 차별점**: 실제 서비스명
- **관련 논문/근거 1~3개**: 제목, 연도, arXiv/DOI/URL (실재 확인한 것만)
- **리스크**: 법·윤리·데이터·기술 리스크
- **자체 점수(1~5)**: 문제심각도 / AI필연성 / 구현가능성 / 데이터확보 / 차별성 / 시연임팩트
